## 元の本文

## 現象

イベントのpayloadとprovenanceは、作った時点で凍結されます。入れ子の辞書は `mappingproxy`、リストは `tuple` になります（`src/sheltersim/events/models.py` の `_freeze_json`）。

ところが、次の4か所は、取り出した値を `isinstance(…, dict)` で確かめています。`mappingproxy` は `dict` ではないので、判定はいつも偽になります。その結果、例外もイベントの失敗も起きないまま、処理が飛ばされています。

| 場所 | 飛ばされている処理 | 起きていること |
|---|---|---|
| `src/sheltersim/experiments/runner.py` 496行 | 経路を閉じたときの `interrupt_staff_trips_on_closed_routes` | 閉じた経路を移動中の職員が、そのまま移動を続ける。呼び出し元はここだけ |
| `src/sheltersim/events/effects.py` 830行 | 予定中の `temporary_room_geometry` の部屋IDを集める | 同じIDの部屋を、予定中のものと重ねて承認できてしまう |
| `src/sheltersim/events/effects.py` 846行 | 予定中の `effect_program_temporary_space` の定員を数える | 予定中の仮設スペースが、定員の確認に数えられない |
| `src/sheltersim/domain/geometry_overlay.py` 1219行 | 介入の仮定ID（`assumption_ids`）を図面変更の履歴に入れる | 履歴の `source_ids` に、介入の仮定IDが残らない |

## 見つけた経緯

#76・#78・#82 を直すときに、同じ原因の箇所を洗い出して見つけました（`develop` の `b9f303f`）。この3件は、凍結済みの値を複製・検証できずに失敗するものでした。こちらの4か所は、失敗せずに黙って処理を飛ばします。

## 直し方の案

判定を `collections.abc.Mapping` にします（`list` を見ている箇所は `tuple` も受け付けます）。それぞれ、生成Scenarioで実際に処理が行われることを確かめるテストを足します。

経路の閉鎖で職員の移動を中断するようになると、経路を閉じるBranchの結果が変わります。#68 の経路の閉鎖のテスト（`test_closing_the_route_into_the_toilets_stops_toilet_use_until_it_reopens`）と、固定された実行結果（`fixtures/regression-contract.json`）への影響を確かめます。
