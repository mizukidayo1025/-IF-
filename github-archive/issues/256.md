## 元の本文

## 現状

履歴索引（`runs/{run}/history.sqlite`、`storage/history_index.py`）への登録に、次の時間がかかっています。100人・生成Scenario、WSL2 上の計測です。

| 場面 | 時間 | 計測した develop |
|---|---|---|
| 1日分の計算での登録（保存48回） | 実時間 約19.5秒、CPU時間 約15.0秒（計算全体の CPU 時間 約70秒のうち） | `82d96cd`（4回） |
| 1440分で分岐したときの、子branchの索引の作成 | 約7.5秒（分岐全体 約16.7秒のうち） | `f80ee74` 相当（#246 を入れた状態、3回） |

1日分の登録の内訳は、#221 の計測（develop `4bd949e`）で次のとおりでした。

- SQLite への書き込み（`executemany`）：8.0〜8.5秒
- commit と close：約2.7秒
- 行ごとの Python 側の処理（個人情報の検査、正準JSON、ハッシュ、IDと検索語の収集）：約5〜6秒

1日で、記録 約11.5万行、関係するID 約127万行、検索語 約84万行を登録します。

## これまでに決めたこと

- 書き込みキャッシュは 16 MiB のままにします。64 MiB にしても、1日あたり約0.9秒しか短くなりませんでした（#221、PR #244 は見送り）。
- 分岐した子branchは、分岐元と共有するイベントと KPI の標本から作る行を、分岐元の索引から写します（#223、PR #246）。写す時間は、分岐の時刻に比例して残ります。

## 案

どの案も、索引の中身か読み方を変えます。そのため、チームで決めてから進めてください。

- **登録する行を減らす**：関係するID（`entities`）と検索語（`tokens`）の行の作り方や索引の張り方を見直し、1回の登録で触るページを減らします。
- **系譜をたどって読む**：子branchには分岐後の行だけを登録し、読むときに分岐元の行もたどります。分岐の時刻によらず、子branchの索引の作成が小さくなります。ただし、検索・一覧・比較の読み方がすべて変わります。

## 注意点

- 索引の内容や読み方を変える場合は、索引の版（`user_version`）と、作り直し（`POST R/index`）の扱いを決める必要があります。
- 索引には、計算中に記録した行動・会話の判断が入っていて、Checkpoint からは作り直せません（#213）。既存の Run の索引をどう移すかも決める必要があります。
- 保存形式、Checkpoint、保存間隔は変えません。

## 完了の条件

- 検索・一覧・比較・会話の結果が、修正前と一致すること
- 1日分の計算での登録時間と、1440分の分岐での子branchの索引の作成時間を、修正前と比べて示すこと
- offline全体テストが成功すること

## 分岐のたびに容量が大きく増える（計測）

100人・7日分の Run（develop `4272b40`）で、9600分の時点から介入なしの分岐を1回すると、Project の容量が約5.0 GB から約8.5 GB に増えました。子 Branch に、親の索引の行（`records`・`entities`・`tokens`）を SQL で写すためです（#223、PR #246）。

- 2回目の分岐は、既定の容量上限（10 GB）を超えて `storage_capacity_exceeded` で失敗しました。途中で失敗した分岐は、索引のない子 Branch を残します（#288）。
- 7日目近くでの分岐 約104秒（#287 を入れた後）のうち、約55秒が行を写す処理です。

デモで7日分の Run から介入を何度か試すには、この Issue の「系譜をたどって読む」案（子 Branch には分岐後の行だけを登録し、読むときに分岐元の行もたどる）が必要です。速さと容量の両方に効きます。5倍高速化の作業の中で、この案を進めます。


### 2026-10-30T07:45:10Z — WaTeR-7

元コメント: https://github.com/jphacks/tkb_2615/issues/256#issuecomment-6517619769 / 更新: 2026-10-30T07:45:10Z

「系譜をたどって読む」案を PR #290 で develop に入れました（`52e2aec`）。分岐した子 Branch は分岐元の行を写さず、分岐の時刻より前の行は分岐元から読みます（索引の版2）。100人・7日分の Run の7日目近くでの分岐は 104.4秒 → 32.4秒、分岐1回で増える容量は約3.5 GB → 約0.1 GB になりました。1回の登録で書き込む量を減らす案（関係 ID と検索語の行の見直し）は、まだ手を付けていません。
