## 起きること

EffectProgram の guard の `eq` は、値の型まで一致することを求めます。そのため、整数で数える項目（行列の長さ、稼働数、区画の人数など）を小数で書いた値と比べると、値が同じでも一致しません。

例：行列が空のとき、`target.queue_length eq 0.0` は偽になります（`eq 0` なら真）。`ne` は逆に、`ne 0.0` が常に真になります。

LLMのコンパイラーの出力（JSON）で、数値が `0.0` のように小数で書かれることは珍しくありません。

## 原因

`events/effects.py` の `_evaluate_guard_node` は、`eq` を `type(actual) is type(expected) and actual == expected` で判定します。真偽値（`staff.available`）と整数を取り違えないためと考えられますが、整数と小数も別の型として扱われます。

## 期待すること

数値（整数・小数。真偽値は除く）どうしは、数として比べること。真偽値と数値は、今までどおり一致させないこと。係数は変えません。

## テスト

このIssue番号付きの `xfail(strict=True)` のテストで置きます。直したら印を外します。
