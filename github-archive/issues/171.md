## 起きていること

`docs/mathematical-models/` にあるモデル一式（suite）の検証結果6つは、suiteが宣言したモデルの一部を使わずに計算されています。#169 の不具合のためです。

| ファイル | 実行したスクリプト | Scenario |
|---|---|---|
| `core-model-suite-validation.json`、`core-model-suite-validation-7d.json`（v1） | `scripts/run_core_model_suite_validation.py` | `fixtures/scenarios/research_operational_100_7d.json` |
| `core-model-suite-v2-validation.json`、`core-model-suite-v2-validation-7d.json`（v2） | 同上 | 同上 |
| `core-model-suite-mechanism-probe.json`（v1）、`core-model-suite-v2-mechanism-probe.json`（v2） | `scripts/run_core_model_suite_mechanism_probe.py` | `fixtures/scenario_100_agents.json`（12人・180分） |

どちらのスクリプトも、`apply_default_model_suite(..., force=True)` でsuiteを入れます。このとき `policy_registry` は `{schema_version: 3, suite_id: ...}` だけになり、領域ごとの指定がありません。実行時のコードの一部は個別のキーだけを読んでいたので、キーがないと昔の既定で動いていました。どちらのScenarioにも図面（`facility_geometry`）はありません。

| 領域 | suiteの宣言（manifestの記録） | 実際に使われたもの |
|---|---|---|
| queue | `need-weighted-physical-queue-v1` | `StrictFIFOQueuePolicy` |
| relationship | `distance-duration-repeat-trust-v1` | `DurationOnlyTrustPolicy` |
| psychology（誤情報の圧力） | `mean-reverting-life-state-v1` | 圧力を計算しない（0） |

psychologyのモデル自体は、宣言どおり使われています。ずれていたのは、行動の判断に渡す誤情報の圧力だけです。v1とv2のsuiteは、queue・relationship・psychologyに同じモデルを宣言しています。そのため、6つすべてが同じ影響を受けています。

結果のJSONの `policy_versions.model_suite` は `@1` です。PR #170 のあとは、個別の指定を省いたsuiteの署名が `@2` になります。そのため、`@1` の記録が直す前の動作で計算されたものだと区別できます。

## 影響を受ける記述

- `13-comprehensive-validation.md`：suiteとbaselineの比較表（例：トイレの待ち行列の人・分 540／851／913、「待機負荷はsuiteとともに増加した」）と、v2のmechanism probeの数値（false claim exposure、終了時誤信念など）
- `14-default-model-suite.md`：v2とv1の7日同seed比較の数値（stress平均 0.9347→0.9019、sleep debt 1,438.6分→981.3分、終了時の高stress率94%、最長episode 9,872分）

待ち行列の負荷と誤情報の経路は、宣言したモデルでは計算されていません。それ以外の数値も、同じRunから出ているので変わる可能性があります。

## 期待すること

PR #170 がマージされたあと、モデル担当が検証結果をどう扱うか決めます。候補は次の2つです。

- 2つのスクリプトをv1・v2で実行し直し、JSONと `13`・`14` の記述を更新する（再実行の手順は `13-comprehensive-validation.md` の最後にある）
- 今の結果を「#169 より前の動作（queue・relationship・誤情報の圧力が昔の既定）で計算したもの」と明記して残し、宣言どおりの結果を別に足す

どちらの場合も、モデルの係数は変えません。実行時の修正は PR #170 で行います。この Issue は、検証結果と文書の扱いだけを対象にします。
