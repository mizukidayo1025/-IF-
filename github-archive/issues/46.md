## 元の本文

## 現状

#37 で、保存境界（30分ごと）の時刻のframeは、計算側がキャッシュしたものを返すようになりました（6時間分のRunの最新時点で1.785秒 → 0.011秒）。#42 で、比較・レポート・会話・Q&Aの読み取りも軽くなりました。次の経路では、まだ全履歴の復元が残っています。いずれもコードを読んで見つけたもので、効果は測っていません。

### 1. 保存境界以外の時刻の表示（`TimelineStore.seek`）

- 30分刻み以外の時刻のtimeline・比較（`GET compare?minute=`）は、直前のCheckpointを全体展開・検証してWorldStateに復元し、最大29tickを再計算します。
- 1440分時点では、復元だけで約8秒かかります（手元の測定）。
- 案:
  - 直近に復元した状態をプロセス内で使い回す（メモリ量に注意）。
  - 再生のように時刻が進む用途では、既存の `replay-frames`（1回の復元から連続して計算する）に寄せる。

### 2. 介入の適用（分岐の作成、`TimelineStore.fork`）

- 1回の分岐で、全履歴のCheckpoint作成が3回前後走ります。
  - `fork_origin` 用の `digest(source.world.to_dict())`
  - `source.checkpoint().checkpoint_hash`
  - `source.fork()` 内の `checkpoint()` と `from_checkpoint()`
- その後に、子branchの保存も続きます。
- 案: 1回のCheckpoint作成の結果を使い回す。
- 分岐の系譜と承認hash（`fork_origin`、`approved_program_hash`）の意味を変えないよう注意してください。

## 完了の条件

- 返すframe・比較・分岐の記録が修正前と一致すること
- 親branch・兄弟branchの状態が変わらないこと
- offline全体テストが成功すること

## 判断：同じ Checkpoint の読み直しに、復元した世界の複製を使う（PR #245）

`ProjectStore` は、最後に読み込んだ2つの Checkpoint について、復元した世界と指標の手つかずの複製を持ちます。同じ Checkpoint をもう一度読むときは、文書の展開と hash の確認を行ったうえで、復元の代わりにその複製のコピーを返します。

### 受け入れたこと
- メモリの増加です。ピークRSS が約60 MiB 増え、読み取りのあとも最後に読んだ2つの世界を持ち続けます。#242 の約47 MiB と合わせると、もとの約830 MiB から約110 MiB の増加です。
- 最初の読み取りは、複製を作る分だけ約0.2秒遅くなります。

### 効果（develop `82d96cd`、WSL2、交互に2回ずつ）
1440分の main と、1380分で分岐して1440分まで計算した child の Project で測りました。

| 同じ Checkpoint の2回目以降の frame（1426・1427分） | 4.28〜4.40秒 | 3.11〜3.35秒 |

## 訂正：#245 の複製が持ち続けるメモリ

#245 の判断のコメントでは「ピークRSS が約60 MiB 増える」と書きましたが、読み終わったあとに残る量を確かめていませんでした。

- 複製は EventLog の記録と予定イベントを元の世界と共有するので、持っている間は元の世界の記録も残ります。
- 1440分の世界1つで、読み終わったあとも Python のメモリが約148 MiB 残ります（複製なしでは約4 MiB）。RSS では 448 MiB と 224 MiB です。
- 持つのは最大2つなので、何もしていない間も最大で Python のメモリ約300 MiB を持ち続けていました。
- 1日分のベンチマーク（`benchmarks/investigate_performance.py`）のピークRSS が約90 MiB 増えた（約835 → 約925 MiB）のも、同じ理由です。ベンチマークは計算後に `load_branch` で読み直しており、そのとき複製を持ったまま、世界をもう1つ組み立てていました。

ローカルの同じ PC でフロントエンドと一緒に動かす使い方では、読み終わったあとまで RAM を占めない方がよいため、PR #258 で、どの読み取りにも使われないまま60秒経った複製を捨てるようにします。計算を始めるときの読み込みでは、PR #257 で複製を作らないようにしました（再開時のピークRSS 約12 MiB 減）。
