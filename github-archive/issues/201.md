## 元の本文

## 何が起きるか

取り込んだ図面（手で描いたトレース・GeoJSON）でScenarioを作ると、給水と配食が一度も始まりません。Scenarioは開始でき（`can_start`がtrue、承認を止める理由なし）、警告に「給水設備のzoneに担当技能（water_service）を持つ職員がいないため、給水は一度も始まりません。」（配食も同じ）と出るだけです。

合成の図面（避難スペース`sleeping`、給水・配食の`food`、トイレの`toilet`の3区画、それぞれ扉でつながる）を取り込み、生成Scenarioの入力（20人、0.25日）で6時間走らせて確かめました。

| | 取り込んだ図面 | 生成Scenario（標準の配置） |
|---|---|---|
| 配った水 | 0 ml（180000 mlのまま） | 4500 ml |
| 配った食事 | 0食（180食のまま） | 9食 |
| 終了時 | 20人全員が`food`に集まり、給水の列に11人 | 列に2人 |

## 原因

`experiments/initial_scenario.py`の`InitialScenarioBuilder.build`は、図面を取り込むと職員を全員1つのZone（`staff`があれば`staff`、なければ`sleeping`）に移します。標準の配置では、給水・配食の技能を持つ職員2人は`food`にいます。図面に`food`があっても移されます。給水・配食は、設備のZoneに担当技能を持つ職員がいないと始まりません。

## 直し方の案

- 職員の元のZoneが図面にあればそのまま残し、なければ、その職員の技能が要る設備のZoneに置く（標準の配置と同じ考え方）。
- あわせて、給水・配食が一度も始まらないScenarioを、警告だけで開始させてよいかも決める必要があります。

## 確かめ方

`tests/integration/test_imported_plan_scenarios.py`に`xfail`（strict）で置きます。

#178 の「図面の取り込み」で見つけました。

#205 で修正しました。取り込んだ図面では、標準の配置と同じ規則（`shelter_staff`）で、給水台・配食台1台につき担当1人をその設備のZoneに置きます。全般の職員は今と同じく `staff`（なければ `sleeping`）です。合成の図面で6時間走らせ、水と食事が配られることを確かめました（`tests/integration/test_imported_plan_scenarios.py` の `xfail` を外しました）。担当がいないときの扱いは、警告のままです。
