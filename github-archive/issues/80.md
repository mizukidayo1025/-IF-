## 元の本文

## 現象

仮設スペースを足す介入（`add_temporary_space`）は、UIで作る生成Scenarioには適用できません。検証で `requires simulator_extensions.enabled and temporary_spaces_v1 state` と出て、Branchを作る前に却下されます。

## 原因（コードで確認済み）

- `temporary_spaces_v1` の状態は、`model_configs.simulator_extensions.enabled` が真のときだけ作られます（`src/sheltersim/domain/simulator_state.py`）。
- 生成Scenario（`InitialScenarioBuilder`）は、この設定を入れません。

## 影響

画面から作ったScenarioでは、仮設スペースの追加を試せません。却下の理由は内部の設定名で、利用者には意味が分かりません。

## 対応の方向（案）

生成Scenarioで、仮設スペースに必要な状態を有効にする。WorldStateとCheckpointの互換性、保存済みRunの再生に影響しないかを確かめる必要があります（AGENTS.mdの不変条件）。#65 と同じく、生成Scenarioで介入に必要な状態が作られていない例です。

## 関連

- #67：`tests/integration/test_intervention_outcomes.py` に、期待する振る舞いを `xfail(strict=True)` で置いています。

元コメント: https://github.com/jphacks/tkb_2615/issues/80#issuecomment-6436567029 / 更新: 2026-10-27T07:50:53Z

#72 を直すときに、仮設スペース（`add_temporary_space`）について次のことを確かめました（`develop` の `98f94d4`）。`simulator_extensions.enabled` を有効にしても、今のままでは適用できません。

1. **予定を作る段階で失敗する**：EffectProgramの状態の検証（`validate_effect_program_state`）が持つ「操作ごとのイベントの種類」の一覧に、`add_temporary_space` がありません。そのため、予定を作った直後に `EffectProgram event type does not match its registered operator` で失敗します（開始は `effect_program_temporary_space`、期限切れは `effect_program_temporary_space_expire` が必要）。
2. **一覧に足しても、適用で必ず失敗する**：`EffectProgramTemporarySpaceHandler._apply` は、承認済みの介入を `temporary_spaces_v1` の状態の `programs` から探します。しかし、この状態の項目は `schema_version`、`policy_version`、`spaces`、`history` だけで、`programs` はありません。開始も期限切れも `temporary-space event does not reference an approved installed effect` で `failed` になります。ほかのハンドラーは `effect_program_v1` の `programs` を見ています。

1だけ直すと、予定を作る時点での却下が、実行中の黙った失敗に変わってしまいます。#72 では直さず、2と一緒にこのIssueで扱うのがよいと考えます。
