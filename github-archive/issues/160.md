## 元の本文

関連：#137（置き換えの途中で見つけた不具合）

## 起きること

Project画面の介入（承認済みの EffectProgram）で分岐した Branch をPDFレポートにすると、介入の数量が落ちます。たとえば、仮設トイレの台数（`count`）や物資の量（`quantity`）です。分析用の facts にも、PDF の本文にも出ません。

## 再現

1. 生成Scenario（`duration_days=1/24`）の時系列を作り、`fork("main", 10, "capacity", program=<add_toilet を count=2 で入れた EffectProgram>)` で分岐させる。
2. `collect_report(api, "p", "r", ["main", "capacity"], 60)` を呼ぶ。

結果は次のとおりです。

- イベントの payload：`{"count": 2, "effect_id": "add-toilets", "modifier_id": ..., "op": "add_toilet", "program_id": ..., "zone_id": "toilet"}`
- レポートの `interventions[0].details`：`{"op": "add_toilet", "zone_id": "toilet"}`（`count` がない）

## 原因

`web/pdf_report.py` の `collect_report` は、介入の `details` に残すキーを限っています。そこに `count` と `quantity` がありません。EffectProgram のイベントは、これらを payload の直下に持ちます。

`integration/test_pdf_report.py` は、Project画面では使わない Branch コマンド（`AddToiletCommand`）で作った Run で確かめているので、この経路を通りません。

## 期待すること

EffectProgram の介入でも、数量がレポートの詳細と分析用の facts に出ること。

## テスト

#137 で、生成Scenarioの EffectProgram で確かめるテストを、このIssue番号付きの `xfail(strict=True)` で置く予定です。
