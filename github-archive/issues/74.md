## 元の本文

## 現象

職員が不在（`set_staff_availability`）の間、支援の依頼は待たされ、時間切れも増えます。ところが、Project画面の「支援を待った理由」のKPIには、この待ちがどこにも数えられません。逆に「職員が忙しくて待った時間」は減って見えます。

生成Scenario（20人・4日、比べるのは最初の6時間）で、唯一の支援担当 `staff_001` を60〜300分不在にした場合の比較：

| | 本線 | 不在 |
|---|---|---|
| 支援の完了（`staff_support_complete`） | 21 | 8 |
| 支援依頼の時間切れ（`support_request_timeout` applied） | 0 | 12 |
| `support_wait_staff_busy_request_minutes` | 463 | 302 |
| `support_wait_staff_off_shift_request_minutes` | 0 | 0 |
| `support_no_qualified_worker_request_minutes` | 変化なし | 変化なし |

## 原因（コードで確認済み）

`src/sheltersim/domain/staff.py` の割り当て処理は、待ちの理由を次の2つでしか数えていません。

- 資格のある職員が作業中（`active_task_id` がある）
- 勤務時間外（`staff_dynamics_on_shift`）

不在の職員はどちらにも当たらず、`_qualified_staff_exists` では「資格のある職員がいる」と扱われます。そのため、不在による待ちはどの理由にも入りません。

## 影響

職員の不在の介入を比べると、KPI上は支援の待ちが改善したように見えます。

## 対応の方向（案）

待ちの理由に「職員の不在」を足す、または `no_qualified_worker` の判定で不在の職員を除く。KPIの項目を足す場合は、スキーマ版と過去のRunの扱いが必要です（AGENTS.mdの不変条件）。

- #65：4日未満の生成Scenarioでは、職員の不在をそもそも適用できません。
