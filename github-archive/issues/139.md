## 元の本文

## 背景

`ruff check .` は、変更に関係なく1801件の指摘で失敗します（2026-10-28 の `develop`）。`ruff format --check .` も148ファイルを整形対象と報告します。CI（`.github/workflows/ci.yml`、手動実行）にはこの2つの手順があるので、実行すると変更に関係なく lint の手順で失敗します。今は「指摘の件数を増やさない」ことだけを確かめています。

内訳は次のとおりです。ほとんどが、snapshot として取り込んだときからある `src/` の長い行です。

| 指摘 | 件数 |
|---|---|
| E501 line-too-long | 1,666 |
| E701 1行に複数の文（`:`） | 71 |
| E702 1行に複数の文（`;`） | 36 |
| I001 importの順序 | 19 |
| F401 使っていないimport | 6 |
| F841 使っていない変数 | 3 |

場所は `src/sheltersim` が1,788件、`tests` が13件です。多いのは `region/facility.py`（119件）、`storage/history_index.py`（84件）、`region/population.py`（83件）、`experiments/initial_scenario.py`（79件）です。

## 試した結果

リポジトリのコピー（`develop` の `b214268`）に `ruff format .` と `ruff check --fix .`（安全な修正だけ）をかけると、次のようになりました。

- 指摘は1801件から321件になりました。残りは、文字列やコメントの長い行（E501）320件と、安全な自動修正の対象外のF841 1件です。`ruff format --check .` は全ファイル整形済みになります。
- 差分は `src/` の255ファイル、12,586行追加・6,119行削除です。
- 整形後のコピーで、長時間テストを除く offline の全件が通りました（960 passed、4 skipped）。長時間テストは実行していません。

## やること

1. **時機をチームで決める。** 差分が大きいので、作業中のブランチと衝突します。数理モデルの実装（`domain/`、`policies/` など）はモデル担当のファイルなので、整形の時機を合わせます。
2. **一括整形のPRを作る。** `ruff format .` と `ruff check --fix .` だけをかけ、動作の変更を含めません。整形のcommitを `.git-blame-ignore-revs` に登録し、`git blame` が整形前の変更をたどれるようにします。全件（長時間テストを含む）の offline 実行で確かめます。
3. **残りを片付ける。**
   - E501 の320件は、主に出典や仮定の説明文です。文字列を分けて書くか、`per-file-ignores` にするかをファイルごとに決めます。出典・仮定の文言そのものは変えません。
   - F841 の1件は、中身を読んで直します。
4. **その後の決まりを書く。** `ruff check .` と `ruff format --check .` が0件で通ることを前提にし、`docs/testing.md` の「通常のoffline確認」を直します。

## 範囲外

- ruff の規則を増やすこと（今の `E`、`F`、`I` のまま）。
- 動作の変更。整形で動作が変わる箇所が見つかったら、別のIssueにします。
- CIの起動条件の変更（AGENTS.md に従い、今の手動実行のまま）。

## 完了の条件

- `ruff check .` と `ruff format --check .` が、`develop` で指摘なしに通る。
- 一括整形のcommitが `.git-blame-ignore-revs` に登録されている。
- offline の全件が整形の前と同じ件数で通る。
