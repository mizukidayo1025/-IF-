## 起きること

Project画面のフォームで、近接接触のモデル（`social_proximity_policy_id: distance-sampled-proximity-v1`）を選んだ生成Scenarioを実行すると、最初のCheckpointの保存で止まります。

```
StorageError: checkpoint contains sensitive data
  storage/projects.py _reject_sensitive_checkpoint_content
  ← storage/checkpoints.py _put
  ← experiments/timeline.py record
```

CLI（`run_scenario`）では最後まで実行できます。ただし、Runの `manifest.json` の `policy_versions["operator:social_proximity"]` が `[REDACTED]` に置き換わり、使ったモデルの記録が失われます。

## 再現

1. 生成Scenarioの入力欄（共通fixtureの `GENERATED_SCENARIO_REQUEST`）に `social_proximity_policy_id: distance-sampled-proximity-v1` を足して、previewを作る。
2. `saved_timeline` でRunを作り、本線を `advance("main", 60, checkpoint_interval=30)` で進める。
3. 最初の保存（30分）で止まる。

## 原因

近接接触のモデルの署名（`domain/simulator_state.py` の `simulator_signatures`）は、次の形です。

```
distance-sampled-proximity-v1@1:state1:distance=1.5:interval=15:pairs=500
```

保存の内容検査（`storage/projects.py` の `safe_document`）は、メールアドレスを `\b[^\s@]+@[^\s@]+\.[^\s@]+\b` で見つけて伏せ字にします。この署名は「@」のあとに小数点（`1.5`）があるので、メールアドレスとみなされます。伏せ字になった値はもとの値と違うため、Checkpointの検査（`_reject_sensitive_checkpoint_content`）は保存を拒否します。

ほかのモデルの署名は「@」のあとに小数点を含まないので、引っかかりません。

## 期待すること

モデルの署名のような値をメールアドレスとみなさないこと。本物のメールアドレス（`name@example.com` など）は、今までどおり伏せ字にすること。

候補：メールアドレスの検出を、ドメインの末尾が英字（`\.[A-Za-z]{2,}`）のものに絞る。

## テスト

次の2つを、このIssue番号付きの `xfail(strict=True)` で置きます。直したら印を外します。
- 近接接触のモデルを選んだ生成ScenarioのRunが、保存を挟んで進むこと（統合）。
- 署名の値は伏せ字にならず、本物のメールアドレスは伏せ字になること（単体）。
