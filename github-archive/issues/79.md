## 元の本文

## 現象

一時外出・転送などの在所の変更（`population_presence`）は、給水か配食を一度でも利用した人に対して実行すると失敗します。記録される理由は `population command failed validation: resource service request history is invalid` です。まだ利用していない人なら成功します。

## 再現

#67 のテスト作成中に確認しました（`develop` の `097ea10`）。

1. 共通fixtureの生成Scenario（20人・6時間）を60分まで進める。
2. `population_presence`（`{"action": "temporary_exit", "expected_return_minute": 240}`）で分岐させる。
   - 対象を `A001`（26分に配食を利用）にすると、イベントが `failed` になる。
   - 対象を `A003`（まだ利用していない）にすると成功し、その人は在所者から外れる。

## 原因（コードで確認済み）

- 一時外出では、その人が `world.agents` から外れます。
- 一方、給水・配食の依頼履歴（`resource_service_v1.request_history`）には、その人の記録が残ります。
- `WorldState.validate`（`src/sheltersim/core/world.py`）は、履歴の `agent_id` が `world.agents` にいることを求めます。そのため、外出後の状態が不正と判定されます。

## 影響

時間が経つほど多くの人が給水・配食を使うので、ほとんどの人について一時外出・転送が使えなくなります。

## 関連

- #67：`tests/integration/test_intervention_outcomes.py` に、利用済みの人での期待する振る舞いを `xfail(strict=True)` で置いています。まだ利用していない人での成功は、通常のテストで確かめています。
