# Issue #65: 断水と職員の不在の介入が、4日未満の生成Scenarioに適用できない

## 元の本文

## 現象

UIで作る生成Scenarioの期間が4日未満だと、次の介入を適用できません。

- 断水（`water_outage`）
- 職員の不在（`set_staff_availability`）
- 物資の到着の延期（`modify_supply_schedule`）

EffectProgramの検証で `effect '…' requires operational_events_v1 state` と出て、Branchを作る前に却下されます。同じ入力でも、期間を4日以上にすると適用できます。

## 再現

#60 のテスト作成中に確認しました（`develop` の `c5acf8c` 以降）。

1. demo-v2のScenario画面と同じ入力（合成市・地震・20人）で、期間だけを変えてpreviewを作る。
2. 生成されたScenarioから `WorldState` を作り、上の介入を `validate_effect_program` で検証する。

| 期間 | 生成される予定イベント | `operational_events_v1` の状態 | 断水・職員の不在 |
|---|---|---|---|
| 0.25日、1日、3日 | なし | なし | 却下される |
| 4日、7日 | `resource_delivery` | あり | 適用できる |

## 原因（コードで確認済み）

- `WorldState.from_scenario` が `operational_events_v1` の状態を作るのは、Scenarioの予定イベントに運営イベントが含まれる場合（`uses_operational_events`）だけです。
- 生成Scenarioの定期補給は4日目から始まるので、4日未満のScenarioには運営イベントがありません。
- その結果、断水や職員の不在が使えるかどうかが、補給の予定があるかどうかという関係のない条件で決まっています。

## 影響

- 短い期間で試算する利用者は、断水や職員の不在を試せません。
- 却下の理由は内部の状態名（`operational_events_v1`）で、利用者には意味が分かりません。

## 対応の方向（案）

- 生成Scenarioでは、予定イベントがなくても `operational_events_v1` の状態を作る。
- または、これらの介入が状態を必要に応じて作れるようにする。

どちらの場合も、WorldStateとCheckpointの互換性、保存済みRunの再生に影響しないかを確かめる必要があります（AGENTS.mdの不変条件）。

## 関連

- #60（介入ごとの結果テスト）では、断水のテストに4日間の生成Scenarioを使い、比べるのは最初の6時間だけにして回避しています。この問題を直したら、短い共通fixtureで確かめるように変えられます。

### 2026-10-27T15:09:26Z — WaTeR-7

元コメント: https://github.com/jphacks/tkb_2615/issues/65#issuecomment-6445619796 / 更新: 2026-10-27T15:09:26Z

#124 を develop にマージしました。既定ブランチが main のため、PR の Closes では自動で閉じないので手動で閉じます。

- **対応**：Issue の案のうち「生成Scenarioでは、予定イベントがなくても `operational_events_v1` の状態を作る」で直しました。生成器が `model_configs.operational_events = {"enabled": true}` を付け、`WorldState.from_scenario` がこの設定でも状態を作ります。0.25日・1日・3日の生成Scenarioで、断水と職員の不在が事前検証を通ることをテストで確かめています。
- **互換性**：設定のない保存済みScenario（これより前に作ったもの、fixture）はこれまでどおりで、保存済みのCheckpointも復元できます。`generated_small` の固定hashは更新しましたが、実際に起きたイベントは変わっていません。
- **残るもの**：物資の到着の延期（`modify_supply_schedule`）は、遅らせる納入がない4日未満のScenarioでは、これまでどおり適用できません（対象がないため）。`docs/effect-program.md` に書きました。
