## 元の本文

## 現象

給水所（`water_station_main`）を食事・給水スペースから避難スペースへ移す `transfer_equipment` は、承認されて適用されます。しかし、移した後は給水が一度も行われません。給水に来た人は列に並んだまま待ち続け、6時間の時点で20人全員が列にいます。

## 再現

#68 のテスト作成中に確認しました（`develop` の `0992842`）。

1. 共通fixtureの生成Scenario（20人・6時間）を60分まで進める。
2. 給水所を避難スペースの `{"x": 5.0, "y": 9.0}` へ移す `transfer_equipment` で分岐させ、360分まで進める。

本線との比較（360分）:

| | 本線 | 移設した子Branch |
|---|---|---|
| 給水の完了（60分以降） | 18件 | 0件 |
| 給水の列 | 2人 | 20人 |
| 渇きの平均 | 0.08 | 0.36 |

列の止まった理由は `staff` と記録されます。

## 原因（コードで確認済み）

- 給水と配食は、施設と同じ区画にいて、担当の技能を持つ職員だけが受け持ちます（`src/sheltersim/domain/resource_service.py` 222行、374行の `person.zone_id == facility.zone_id`）。
- `transfer_equipment` は施設の区画を変えますが、担当の職員（`staff_002`・`staff_003`）は元の区画に残ります。職員が新しい区画へ向かう仕組みはありません。
- 適用前の検証（`validate_geometry_change`）も、移設先に担当の職員がいるかどうかを見ていません。

## 決めること

次のどちらにするかは、運用モデルの持ち主の判断です。

- 職員の要る施設を移したら、担当の職員も移す（または移動の作業を作る）。
- 担当の職員がいない区画への移設を、適用前に却下する。

## 関連

- #68：`tests/integration/test_intervention_outcomes.py` に、期待する振る舞いを `xfail(strict=True)` で置きます。
- 職員の要らないトイレの移設は、期待どおりに働きます（#68 のテスト）。
