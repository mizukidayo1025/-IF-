## 何が起きるか

図面の取り込みで、型や参照の誤りのいくつかが、理由付きで拒否されず、想定外の例外で落ちます。HTTPでは500（`project operation failed`）になります。取り込む図面は利用者が作る信頼しない入力なので、ほかの誤りと同じように拒否されるべきです。

誤り41種類（手で描くトレース・候補の確認）と37種類（GeoJSON）を入れて確かめ、次の7種類が落ちました。

| 入口 | 誤り | 例外 |
|---|---|---|
| トレース | 設備の占有範囲（`equipment_footprints`）を持つ施設が、未知のZoneを指す | `StopIteration`（`trace_uploaded_plan`の`next(...)`） |
| GeoJSON | `width_m`がオブジェクト | `TypeError`（`float()`） |
| GeoJSON | Zoneの`usable_area_m2`がnull | `TypeError`（`float()`） |
| GeoJSON | Zoneの`usable_area_m2`が配列 | `TypeError`（`float()`） |
| GeoJSON | 経路（LineString）の`coordinates`が数値 | `TypeError`（反復できない） |
| GeoJSON | 経路の`coordinates`がnull | `TypeError`（反復できない） |
| GeoJSON（旧形式の封筒） | `zones`が配列でない | `TypeError`（反復できない） |

ほかの誤り（未知のZone・壁・開口の参照、閉じた壁を横切る経路、重なるZone、面積のないZone、NaN・無限大の座標、ページの不一致など）は、どれも理由付きで拒否されました。

## 確かめ方

`tests/unit/web/test_plan_services.py`に`xfail`（strict）で置きます。

#178 の「図面の取り込み」で見つけました。
