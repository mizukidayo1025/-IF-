## 元の本文

## 概要

初期Scenarioを作るときに、地域の行政データを決定的に（同じ条件なら同じ結果になる方法で）取得できるようにしたいです。そのために、自然文の入力から公開APIの引数（自治体コード、気象庁の地域コード、e-Statの統計表など）を決める部分にClaudeを使う、という設計案です。

値そのものは、これまでどおり公開APIから決定的に取得します。Claudeは、決定的に集めた候補の中から選ぶだけにします。いまの「Claudeのweb検索で出典のURL候補を集める」機能の扱いも、あわせて決めたいです。

## 背景：墨田区での確認結果（main `a409a5f`、Claudeなし）

| 取得元 | 結果 |
|---|---|
| 国土地理院 住所検索 | 「東京都墨田区」など3件。自治体コードは返らない |
| 国土地理院 指定避難所CSV | 自治体コード`13107`を指定すると、指定避難所39か所の名前・住所・位置を取得できる（#23で修正済み）。定員・面積は、データにないため空 |
| 気象庁 予報 | 地域コード`130000`で、東京地方の天気・気温・降水確率・風の28件 |
| e-Stat | `ESTAT_APP_ID`が未設定のため使えない |
| 自治体の計画・ハザード（`SHELTERSIM_REGION_DATA_SOURCES_JSON`） | 未設定のため使えない |

## 現状の流れと、欠けているところ

| 段階 | 現状 |
|---|---|
| 自然文 → Scenarioの項目 | ある。`region-scenario-extraction-v1`で、自治体名・災害・人数などを取り出す |
| 項目 → 公開APIの引数 | **欠けている。** 次の引数は、利用者が手で選ぶか入力する必要がある |
| 公開APIの引数 → 値 | ある。国土地理院・気象庁・e-Statのproviderで取得する |
| Claudeのweb検索 | 上の流れとは別。go.jp・lg.jpの出典URL候補を最大25件出すだけで、値はScenarioに入らない |

利用者が手で決める必要がある引数は次のとおりです。

- 自治体コード：指定避難所CSVとの照合で候補が出るので、そこから選ぶ
- 気象庁の地域コード：手で入力する
- e-Statの表ID、地域、時点、分類：手で入力する（`EStatProvider`は表を勝手に選ばない設計）

## 提案

1. **候補は決定的に集める**
   - 自治体：住所検索と、指定避難所CSVの自治体候補（`GsiShelterLookup.municipality_candidates`）
   - 気象庁の地域コード：気象庁の地域一覧。取得する処理はまだないので、新しく作る必要がある。取得先の仕様も確認が必要
   - e-Statの統計表：`EStatProvider.search_tables`と`describe_table`の結果
2. **Claudeは、その候補の中から選ぶだけにする**
   - 出力スキーマで、選べる値を候補の列挙に限る。存在しないコードや表IDは返せない
   - 選んだ理由を短く添える
   - 入力は、自然文と候補の一覧だけにする。web検索は使わない
3. **意味の検証をしてから、利用者に承認してもらう**
   - 選んだ値が候補に含まれているか
   - 自治体コード、気象庁の地域、e-Statの地域が同じ地域を指しているか
   - 検証に通った値をプレビューに示し、利用者が承認してから公開APIを呼ぶ（AGENTS.mdの「LLM出力は信頼しない入力として扱う」に沿う）
4. **offlineやfallbackのときは、規則で決めるか、利用者が選ぶ**
   - 候補が1件で名前が一致する場合は、Claudeを使わずに決めてよい（墨田区はこれに当たる）
   - 応答はresponse tapeに記録し、同じ入力なら同じ結果を再現できるようにする

## web検索の扱い（決めたいこと）

- 1回の呼び出しで、入力を100万トークンと見て約$8.2を確保します（`src/sheltersim/llm/accounting.py`）。実際の費用は数十セントの見込みですが、計測していません。いまはAPIキーがあれば、下書きごとに自動で呼ばれます。
- 値はScenarioに入りません。利点は、地域防災計画や避難所運営マニュアルのような、公開APIにない資料を人が探す手がかりになることだけです。
- 選択肢：
  1. 橋渡しに置き換えて削除する
  2. 既定では無効にし、利用者が明示したときだけ呼ぶ
  3. 今のまま残す

## この案でも取れないもの

- 避難所の面積・定員・備蓄量は、国の公開APIにありません。チームから要望があった「その土地の行政データで量を決める」をそこまで実現するには、自治体のオープンデータを設定式のproviderに登録するか、利用者が出典付きで入力する必要があります。
- 統計（年齢構成・世帯人員）を取るには、`ESTAT_APP_ID`（無料の利用登録）が必要です。

## あわせて直したい小さな問題

- 入力が「墨田区」、データが「東京都墨田区」のとき、「入力自治体名との完全一致は確認できませんでした」と警告が出ます。都道府県名を付けていないだけの入力に対しては、出なくてよいはずです。
