## 元の本文

## 何が起きるか

Project画面の「条件と出典を整理」（Scenarioのプレビュー）は、地域の調べ（`region/research.py`の`RegionResearchService.research`）で公開サービスを呼びます。公開サービスが取得できないときは「不明」（`unknowns`）として扱い、プレビューは続ける作りです。ところが、次の失敗では例外が調べの外へ出て、プレビュー全体がHTTP 500（`project operation failed`）で失敗します。

外部サービスを偽の応答に置き換え、5種類のサービス × 12種類の失敗で確かめました（ネットワークには出ていません）。

| サービス | 失敗 | 例外 |
|---|---|---|
| 国土地理院の住所検索、e-Stat（`providers._get_json`） | 応答の前に接続が閉じる・リセットされる | `ConnectionResetError`（実際のurllibでは`http.client.RemoteDisconnected`） |
| 同上 | 読み取り中に接続がリセットされる | `ConnectionResetError` |
| 同上 | 応答が途中で切れる | `http.client.IncompleteRead` |
| 気象庁の予報、設定した地域の公開データ（`additional_providers._download_json`） | 応答が途中で切れる | `http.client.IncompleteRead` |
| e-Stat | JSONが配列・文字列・null（オブジェクトでない） | `AttributeError`（`_get_json(url).get(...)`） |

ほかの失敗（HTTPエラー、接続できない、JSONでない、形の違うJSON、空の応答）は、どのサービスでも「不明」として扱われました。国土地理院の避難場所のCSVは、どの失敗でも止まりませんでした。

## 原因

- `providers._get_json`は、`opener.open`と`response.read`の例外のうち、`HTTPError`・`URLError`・`TimeoutError`・`socket.timeout`だけを`RegionProviderError`にしています。urllibは、接続後の応答待ち（`getresponse`）と読み取りの例外を`URLError`に包まないので、`RemoteDisconnected`・`ConnectionResetError`・`IncompleteRead`がそのまま出ます。
- `additional_providers._download_json`は`OSError`まで捕まえていますが、`IncompleteRead`（`http.client.HTTPException`）は捕まえていません。
- `EStatProvider`の3つの関数は、応答がオブジェクトであることを確かめずに`.get`を呼んでいます。

## 確かめ方

`tests/unit/region/test_research.py`に`xfail`（strict）で置きます。

#178 の「外部データの接続」で見つけました。

#211 で修正しました。国土地理院の住所検索とe-Statの取得（`_get_json`）は、`OSError` と `http.client.HTTPException`（応答前の切断、読み取り中のリセット、途中で切れた応答）を「取得できない」として扱います。気象庁の予報と地域の公開データの取得（`_download_json`）も、途中で切れた応答を同じく扱います。e-Statは応答がJSONのオブジェクトであることを確かめます。失敗したサービスは「不明」になり、プレビューは返ります。`tests/unit/region/test_research.py` の `xfail` 10件の印を外しました。
