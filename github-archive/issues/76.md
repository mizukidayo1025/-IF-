## 元の本文

## 現象

物資の到着を遅らせる介入（`modify_supply_schedule`）を使うと、遅らせた物資が届く時刻にシミュレーションが例外で止まります。

```
File "src/sheltersim/events/handlers.py", line 828, in apply
    ledger_event = ScheduledEvent(
ValueError: event payload and provenance must contain finite JSON values
(TypeError: Object of type mappingproxy is not JSON serializable)
```

遅らせない場合は、同じ物資が問題なく届きます。

## 再現

#66 のテスト作成中に確認しました（`develop` の `cd419f8`）。

1. 共通fixtureの入力に、運営条件として「水1L」と「120分に水100Lが届く予定（`resource_delivery`）」を足して生成Scenarioを作る。
2. 60分で分岐させ、`region-shipment-001` を300分へ遅らせる `modify_supply_schedule` を適用する。
3. 分岐先を300分以降へ進めると、到着の処理で止まります。

## 原因（コードで確認済み）

- `ResourceLedgerHandler.apply` は、到着したイベントから台帳用のイベントを作り直します。このとき `provenance=dict(event.provenance)` で、一番外側だけを辞書にしています。
- 遅らせた到着イベントのprovenanceには、EffectProgram由来の入れ子の値（`mappingproxy`）が入っています。そのため、JSONに変換できずに失敗します。
- 遅らせていない到着イベントには入れ子がないので、通常は表に出ません。

既存の `tests/test_operational_events.py` の遅延テストは、fixtureのScenarioで時刻を手で動かしており、この経路を通っていませんでした。

- #66：`tests/integration/test_intervention_outcomes.py` に、期待する振る舞いを `xfail(strict=True)` で置いています。直したら印を外してください。
