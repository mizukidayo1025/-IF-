## 起きること

CLI（`run_scenario`）でRunを実行すると、`manifest.json` の `policy_sources.*.reference`（モデルの出典）の一部が `[REDACTED]` に置き換わります。使ったモデルの根拠が、Run成果物から読めなくなります（AGENTS.mdの「provenanceをRun成果物に残す」に反する）。

生成Scenario（近接接触のモデルを選んだもの、30分）では、次の5件が置き換わりました。

| モデル | 出典（一部） | 一致した部分 |
|---|---|---|
| `degroot-contact-v1` | `doi:10.1080/01621459.1974.10480137` | `01621459.1974.10480137` |
| `expressiveness-channel-openness-v1` | `…/10.1007/s10458-012-9201-1` | `012-9201-1` |
| `mean-reverting-distress-v1` | `doi:10.1177/0956797610372634` | `0956797610372634` |
| `mean-reverting-life-state-v1` | 同上 | 同上 |
| `sparse-family-zone-contact-v1` | `doi:10.1111/1467-8721.ep10770953` | `1467-8721` |

## 原因

`inspection/traces.py`（Run成果物）と `web/inspector.py`（保存したRunの表示）は、電話番号を `(?<!\w)\+?\d[\d ().-]{7,}\d(?!\w)` で見つけます。数字が8桁以上並んだり、`-` や `.` で区切られた数字の並びに広く一致するので、DOIの番号や日付（`2026-10-28`）も電話番号とみなします。一致した文字列は、値全体が `[REDACTED]` になります。

保存の内容検査（`storage/projects.py` の `_PHONE`）は、区切りのある3つの数字の組だけを見るので、これらには一致しません。

## 期待すること

モデルの出典のDOIや日付を電話番号とみなさず、Run成果物に残すこと。本物の電話番号（`090-1234-5678`、`+81 3 1234 5678` など）は、今までどおり伏せ字にすること。

どこまで検出を絞るかは、プライバシーとの兼ね合いで決める必要があります。候補は次のとおりです。
- 保存の内容検査と同じ定義に揃える。
- `doi:`・`https://` の中や、ISO日付の形を除く。

係数は変えません。

#193 で直しました（develop にマージ済み）。電話番号の検出を保存の検査と同じ定義（storage/projects.py の PHONE_NUMBER。区切りのある3つの数字の組）にまとめ、Run成果物と保存したRunの表示でも使います。モデルの出典のDOIや日付は伏せ字になりません。区切りのない数字の並びは、保存の検査と同じく検出しません。
