## 起きること

一時外出した人を、EffectProgram の `population_presence`（`action: return`）で区画に戻すとします。帰還の判定は、その区画へ通常の移動で向かっている人を数えません。そのため、空きのない区画へ帰還させてしまい、移動中の人が着いたときに定員を超えます。シミュレーションは、毎tickの検証で例外を出して止まります。

```
StateInvariantError: zone 'staff' exceeds nominal plus approved temporary or physical-room capacity
  core/engine.py step → world.validate
```

## 再現

1. 生成Scenario（共通fixtureの入力欄、`duration_days=1/12`）の `staff` 区画の定員を1にする。
2. 本線を10分まで進める。10分で分岐し、A019 を一時外出させる（`action: temporary_exit`）。
3. その分岐を20分まで進める。20分で分岐し、A019 を `staff` 区画へ帰還させる（`action: return`、`zone_id: staff`）。
4. 分岐を進めると、22分で止まる。

20分の時点で、`staff` 区画は空いています。ただし、A001 が `staff` へ移動中です（`activity: moving`、`target_id: staff`）。帰還は、空きがあるとしてA019を入れます。22分に A001 が着き、定員の1を超えます。

介入のない本線は、定員1のままでも120分まで進みます。

## 原因

`domain/population_lifecycle.py` の `_zone_has_room` は、区画にいる人と、帰還の移動（`travel_return` の作業）で向かっている人だけを数えます。通常の移動で向かっている人は数えません。

帰還させられないときに待たせる仕組み（`pending_returns` と `admit_pending_returns`）はありますが、この判定が空きを多く見積もるため、待たせずに入れてしまいます。`relocate` の目的地の判定も、同じ関数を使っています。

## 期待すること

帰還（と移動）の空きの判定が、区画へ向かっている人の入り方と同じ基準で数えること。空きがなければ、`pending_returns` で待たせること。シミュレーションが例外で止まらないこと。係数は変えません。

## テスト

生成Scenarioで、移動中の人がいる区画へ帰還させるテストを、このIssue番号付きの `xfail(strict=True)` で置きます。直したら印を外します。
