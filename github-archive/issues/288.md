## 元の本文

## 起きていること

分岐（`TimelineStore.fork`）が子 Branch の保存の途中で失敗すると、子 Branch の pointer（`branch.json`）と Checkpoint だけが残り、履歴索引に子 Branch の行がない状態になります。

- `TimelineStore.record` は、Checkpoint と Branch の pointer を保存（`save_captured_branch`）してから、索引に登録します（`HistoryIndex.ingest`）。
- 登録で失敗すると、pointer はもう保存されています。
- 同じ子 ID で分岐し直すと、`child branch already exists` で断られます。

## 再現（計測の途中で起きたこと）

100人・7日分の Run（develop `4272b40`、容量 約8.5 GB）を、9630分で分岐しました。子の索引の行を写す途中で、容量の上限（10 GB）を超えて `storage_capacity_exceeded` になりました。その後、Branch `f9630` は存在しますが、索引に行がありません。

## 決めること

- 失敗した分岐で作った pointer・Checkpoint を消すか、索引の登録を後から続けられるようにするか。
- 容量の超過は、7日分の Run では2回目の分岐で起きます。分岐のたびに親の索引の行（約3.5 GB）を写すためです（#256）。

関連：#256、#287


## 元の会話

### 2026-10-30T09:27:17Z — WaTeR-7

元コメント: https://github.com/jphacks/tkb_2615/issues/288#issuecomment-6519463381 / 更新: 2026-10-30T09:27:17Z

解決したので閉じます。

- 分岐が子 Branch の保存の途中（索引への登録）で失敗したとき、子の pointer と状態を消してから誤りを返すようにしました。Branch の一覧に索引のない子が残らず、同じ ID で分岐し直せます（PR #294、develop `6d734a7`）。
- 分岐のたびに分岐元の索引の行を写して容量の上限を超える原因は、子 Branch が分岐元の行を写さずに系譜をたどって読む形でなくしました（PR #290、develop `52e2aec`）。7日分の Run での分岐1回で増える容量は、約3.5 GB から約0.1 GB になりました。
