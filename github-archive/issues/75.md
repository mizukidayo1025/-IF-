## 元の本文

## 現象

UIで作る生成Scenarioの職員は、清掃（`cleaning`/`sanitation`）と保守（`maintenance`/`repair`）の技能を持ちません。そのため、職員への作業指示（`staff_task_order`）のうち清掃と保守は、必ず `staff task order worker lacks the registered task skill` で却下されます。

20人の生成Scenarioの職員と技能：

| 職員 | 技能 |
|---|---|
| `staff_001` | support, intake, information, water_service, meal_service, medical_support |
| `staff_002`、`staff_003` | water_service, meal_service |

指示できる作業は、`staff_001` による巡回・情報提供・受付だけです（`src/sheltersim/domain/staff_operations.py` の `_TASK_SKILLS`）。

## 確かめたいこと

- 生成Scenarioの職員に清掃・保守の技能がないのは、意図した設計か。
- 意図した設計なら、清掃・保守の指示を受け付けない理由を、利用者に分かる言葉で返す必要がありそうです。
- 技能を後から与える介入（`set_staff_role`）は、今は例外で止まります（別Issue）。

## 関連

- #66 のテスト作成中に見つけました。#66 では、巡回の指示で結果テストを書いています。


## 元の会話

### 2026-10-27T15:48:08Z — WaTeR-7

元コメント: https://github.com/jphacks/tkb_2615/issues/75#issuecomment-6446559400 / 更新: 2026-10-27T15:48:08Z

#125 を develop にマージしました。既定ブランチが main のため、PR の Closes では自動で閉じないので手動で閉じます。

Issue の「確かめたいこと」への回答です。

- **意図した設計か**：意図した設計として扱うことにしました。避難所の清掃は避難者の当番や自治組織が、設備の修理は施設管理者や業者が担うことが多いので、生成Scenarioの職員には清掃・保守の技能を与えません。修理は介入の修理の手配（`facility_repair`）で表します。理由は `docs/simulation-models.md` に書きました。
- **利用者に分かる理由**：作業指示を受けられる職員がいないときは、承認前に日本語の理由を返すようにしました。誰も技能を持たなければ `no_qualified_staff`（担当変更、保守なら修理の手配も案内）、ほかの職員が持っていれば `staff_lacks_task_skill`（その職員を挙げる）です。
- **技能を後から与える介入**：`set_staff_role` は #72 で直っており、却下の理由でも案内しています。

避難者の当番による清掃のように区画の衛生度を回復させる仕組みはまだなく、長いRunでは衛生度が下がり続けます。この点は文書に書きました。モデルを足すかどうかはこの Issue の範囲外です。
