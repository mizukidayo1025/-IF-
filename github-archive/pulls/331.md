## 概要
Rust が `body_state_v1` を持ち、毎 tick と毎イベントの書き手を一緒に移します（`state/body_state.rs`、`rules/body_state.rs`）。`record_social_event` と `apply_state_deltas` が Rust で動きます。処理の世話や衛生の書き込み、人の出入りは Python から1件ずつ転送します。詳細は `docs/rust-port/lanes/m3-body-state.md` にあります。

レーン I が測った +16%（規則なしで持つ場合）は、規則を一緒に移すと消えました。

やめた確認：`body_agents_valid`、`body_relationships_valid`、`_pair_key_is_good`、`_GOOD_KEYS`、`body_watch`。証明とテストは文書にあります。

## 速さ
- `tick_budget.py`（9600分から480 tick、3回、`eef13e7`）：比 1.007、A/A 1.009、load average 3〜4。**tick は速くも遅くもなっていません**
- `record_social_event`：約200 → 約130 µs/tick。毎 tick の `validate_body_state`：約113 → 約46 µs/tick
- 7日分（静か）：実時間 103 秒、スレッド 88 秒（1回）

## social_network との統合（`e657934`、`ac275df` を含む）

## 確かめていないこと
- 行の検証が受け入れると、記録と関係の Python の規則は動きません。`dict.__setitem__` で木に直接書いた値は行に届かないので見えません（レーン T の穴と同じで、テストが固定しています）。
- 7日分は `social_interaction` だけで、ほかの3種類（`information_contact_update`、`proximity_contact_update`、`information_correction`）はゲートとテストだけが比べます。
- taint した世界は、watch がなくなったので関係を毎 tick 読み直します。ゲートと7日分では起きていません。
- 分岐が少し遅いかもしれません（レーン 7.9〜9.3 秒、基準 7.4〜8.7 秒、3回）。RSS は測っていません（タグで測ります）。
- Windows と macOS はこの PR の CI で確かめます。
