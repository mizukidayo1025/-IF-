## 元の本文

Checkpoint の保存で、同じ計算の中で前に保存した list の chunk は、byte 列とハッシュを作り直さずに key を使い回します。

## 修正前

- 保存のたびに、list（EventLog やKPIの標本など）を128件ずつに分けた chunk すべてについて、次の処理を行っていました。
  1. 項目のbyte列をつないで chunk のbyte列を作る
  2. SHA-256 で key を求める
  3. ファイルがあるか確かめる
- 1440分の EventLog だけで約300個の chunk があり、その大半は前の保存と同じです。

## 変更

- 計算の間、履歴キャッシュ（#44）は、前に保存した項目の正準JSONのbyte列を同じオブジェクトのまま使い回します。
- 保存した chunk の key を、最初と最後の項目のbyte列オブジェクトと件数ごとに覚えます（`CanonicalEncoder.chunk_key` / `remember_chunk`、履歴キャッシュが計算の間持ちます）。
- キャッシュは前に保存した項目を先頭から順に使い回し、新しい項目だけを後ろに足します。そのため、最初と最後が同じオブジェクトで件数が同じなら、間の項目も同じで、chunk のbyte列も同じです。
- 覚えた key の chunk のファイルがあれば、byte列とハッシュを作らずにその key を使います。ファイルがなければ（拒否された保存など）、これまでどおり作ります。
- 新しい chunk の個人情報の検査、圧縮、書き込みは、これまでどおりです。
