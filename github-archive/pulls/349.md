## 分かっている弱点

- 感度：パトロールの信頼 0.1、割り当ての期限 +1、インフラの優先度はハッシュ、シャドー、テストが検出します。比例の衛生の式、苦情 0.02、協力の信頼 0.01、訂正の上限 0.95、うわさの信頼の重み 2.0、ケアの既定値 0.03 の 1% はハッシュでもシャドーでも見えず、テストだけが検出します。そのうち 5 つは最初の実行で漏れたのでテストを足しました。
- `assign_work` のシャドーはコントローラーを浅くコピーするので、入れ子のコンテナは共有です。差は出ていませんが、シャドーの仮定です。
- Rust の kernel はほかのレーンの規則を名前で呼びます。名前が変わると、最初の書き込みの前なら拒否し、その後なら例外が出ます。
- driver とのマージで、単独で選んだこのシャドーが素通りされないように `python_path_only` を足しました。`interventions` 1 シナリオで確認しました（数が 0 でなく、`Error in sitecustomize` なし）。
- Rust の行の網羅は測っていません。Linux 以外は CI に任せます。
