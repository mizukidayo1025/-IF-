## 元の本文

tick の段階の時間を約半分にします。人の状態の持ち主を Rust に移す作業は含みません。残りの時間の多くは `domain`・`events` の Python の規則（B4 の範囲）なので、状態だけ移しても大きくは減らないと判断しました。B2 の合格条件のうち、この部分は未達で、`docs/rust-port.md` にもそう書いています。

## 変更
- **Rust へ移した計算**（`native/src/contacts.rs`）: 社会の伝播（`ExpressivenessChannelOpennessPolicy.update`）と、メッセージ・信念・支援依頼の記録がない間の情報の接触（`InformationSpreadPolicy.update`）。浮動小数の演算順、乱数のキー、同順位の規則は Python と同じで、係数は変えていません。
- **ハッシュの変わらない Python の変更**: `WorldView.from_world` の組み立て、`selected_models` の段階内共有、`update_psychological_state` の `deepcopy` 削除、閉じた経路の再利用、`dispatch_due` のキュー検索など。
- **フォールバック**: trace が OFF 以外のとき、値の型が想定外のとき、状態が不正なとき、他のモデルのときは Python で計算します。`SHELTERSIM_NATIVE=0` でも従来どおり動きます。

## モデル担当の方に見ていただくところ
- `native/src/contacts.rs` の、上記2つのモデルの式
- 重みの合計が0の接触がある人では、Python の更新が `zip(strict=True)` の `ValueError` を出します。Rust もその入力を Python に戻すので、同じエラーになります（動作は変えていません）。
