## 元の本文

## 概要

`tests/integration/test_process_worker.py::test_two_branches_of_a_run_compute_at_once` が、PR #287 の Windows の CI で失敗しました（`assert len(multiprocessing.active_children()) == 2` が 1）。テストの書き方が計算の速さに依存していたためで、#287 の変更とは関係ありません。

## 原因

このテストは、同じ Run の2つの Branch に30分ずつの計算を頼み、2つ目を頼んだ直後に「子プロセスが2つ動いている」ことを確かめていました。Windows ではプロセスの起動に数秒かかります。今日の高速化（#280〜#286）で計算が速くなり、2つ目のプロセスが起動するまでに、1つ目の30分の計算が終わることがありました。

## 変更

- 2つの Branch に、それぞれ600分の計算を頼みます。プロセスの起動よりずっと長いので、確かめる時点で両方とも動いています。
- 「2つとも動いていて、Run と各 Branch の状態が running」を確かめた後、取り消します。
- 最後は、どちらも `paused` で、目標の600分より前で止まったことを確かめます（取り消した時刻の状態を保つので、30分の区切りとは限りません）。
- 計算を待たずに取り消すので、テストの時間は前と同じくらいです（手元で約1秒）。
