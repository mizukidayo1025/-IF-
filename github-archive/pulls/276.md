## 元の本文

`オフラインCI`（`.github/workflows/ci.yml`）を、Linux・Windows・macOS の3つで流し、develop への Pull Request のたびに自動で走らせます。#48 の段階3で Windows を対応環境に含めるため、3つの OS で動くことを確かめる仕組みとして、利用者に依頼されて追加します。AGENTS.md の「依頼で明示された場合に限り CI トリガーを変更する」に当たります。

## 変更
- `ubuntu-latest`・`windows-latest`・`macos-latest` のマトリックスにしました。1つの OS が失敗しても、ほかは最後まで流します（`fail-fast: false`）。
- テストを `-n auto` で並列に流します。これまでは並列にしていませんでした。
- OS ごとの `.test-results/` を、`test-results-<OS>` の artifact として7日間保存します。隠しフォルダーなので `include-hidden-files: true` が要ります。
- lint と format の確認は、Linux だけで行います。
- 起動条件：
  - develop への `pull_request` を足しました。
  - `workflow_dispatch`（手動）は残しています。
  - 同じブランチや PR で新しい実行が始まったら、古い実行は取り消します（`concurrency`）。
- 依存関係は、pip のキャッシュ（`actions/setup-python` の `cache: pip`）で入れます。
- `docs/testing.md`：CI の起動条件、3つの OS、Windows の所要時間、artifact の保存を書きました。

途中で、Windows の実行環境で Microsoft Defender のリアルタイムスキャンを止める手順を試しました。テストの時間は約6%（2,463 → 2,305秒）しか縮まず、実行ごとのばらつきの範囲だったので、戻しています（`febb105` と、それを戻した `793bf0f`）。

## 所要時間（このブランチの手動実行、テストの部分）

| OS | 結果 | 時間 |
|---|---|---|
| Linux | 1335 passed、4 skipped | 約4〜6分 |
| macOS | 1333 passed、6 skipped | 約5〜6分 |
| Windows | 1332 passed、7 skipped | 約13〜15分 |

- 結果がそろうまでの時間は、Windows で決まります。相談のうえ、Windows でも全テストを流すことにしました。
- Windows で見つかった不具合（Ctrl+C を送るプロセスの確認、Run を削除できない、保存と重なった読み取りの 500、日本語の入出力）は、どれも計算や保存の流れを通るテストで見つかりました。一部のテストだけにすると、見逃しやすくなるためです。
- Windows で skip するテスト：
  - ライブ API のテスト（4件、どの OS でも skip）
  - Linux の open-file-description ロックが要るテスト（2件）
  - 容量を数えている間に消えたファイルのテスト（#274）
