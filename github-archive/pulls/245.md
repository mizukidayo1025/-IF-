## 元の本文

復元した状態をメモリに持ち続ける PR です。持ち続ける量（最後に読んだ2つの Checkpoint の世界）と、それによるメモリの増加の判断は #46 に書きました。

## 変更

- `ProjectStore` は、最後に読み込んだ2つの Checkpoint について、復元した世界と指標の手つかずの複製を、checkpoint hash ごとに持ちます。2つにしたのは、比較と再生が2本の branch を読むためです。
- 同じ Checkpoint をもう一度読むときの動き:
  - 文書はこれまでどおりディスクから展開し、manifest、chunk、`checkpoint_hash`、`state_hash` を確かめます。世界のJSONは1回だけ作ります。
  - 復元（`WorldState.from_dict` と、その前の文書のコピー）は行わず、持っている世界の複製を渡します。
  - Checkpoint の文書は content-addressed で変わらないので、同じ hash の文書から復元した状態は同じです。
- 複製は `deepcopy` で作ります。変更されない EventLog の記録と予定イベントは、複製の間で共有します（1440分の世界で約0.16秒）。
- 確認を1回の世界のJSONで行うため、`Checkpoint._validate` のハッシュ確認を `_verified_world_bytes`・`_verify_body_hash` に分けました。振る舞いは同じです。
