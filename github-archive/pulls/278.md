## 元の本文

#48 の段階3の画面側です。#277 で、同じ Run の複数の branch を同時に計算・分岐できるようになり、branch ごとの計算の状態（`branches[].status`）が API に付くようになりました。この PR では、Project 画面がそれを使うようにします。

## 変更（`static/project.js`）

これまでの画面は、Run の状態を見ていました。Run の状態は、どれかの branch が計算中なら `running` です。そのため、1本でも計算中だと、すべての branch のボタンが無効になり、分岐の作成中の表示もほかの branch の計算が終わるまで続いていました。

- `branchState(data, branch)`：選んでいる branch の計算の状態を返します。branch の状態の記録がない Run（#277 より前に計算した Run）では、これまでどおり Run の状態を使います。
- 計算・分岐・プレビューのボタンは、**選んでいる branch** が計算中のときだけ無効にします。
- branch の一覧に、計算中の branch は「· 計算中」と表示します。計算済みの範囲の表示と状態の行は、選んでいる branch の状態を示します。状態の行には Run の状態も残します。
- 分岐の作成中の表示は、子 branch が一覧に現れて計算中でなくなったら終わります（子 branch を開きます）。`last_fork` が失敗を示した場合も終わります。ほかの branch の計算は待ちません。
- 取消しボタンは、選んでいる branch の計算だけを止めます（`POST …/cancel` に `branch_id` を渡す）。
- レポートを読み直すきっかけも、選んでいる branch の計算が終わったときにしました。

## 確認

ヘッドレスの Chromium（Playwright）で、実際のサーバーを `--max-parallel-runs 2` で動かして確かめました。使ったのは、main と child がどちらも1200分まで計算済みの Run です。

1. child を開いて1440分まで計算を始めると、child の計算・分岐のボタンが無効になりました。
2. main に切り替えると、Run の状態は `running` のままでも、main の計算・分岐・プレビューのボタンは使えました。
3. main も計算を始めると、一覧が「child · 1200–1200 · 計算中」「main · 0–1200 · 計算中」になりました。
4. main を選んで取消しを押すと、main だけが `paused` になり、child は計算を続けました。状態の行も「Branch main · paused」になり、main の計算ボタンが使えるようになりました。
5. 最後は、child が1440分で `completed`、main が1200分で `paused`、Run が `completed` になりました。

ページの JavaScript のエラーはありませんでした。
