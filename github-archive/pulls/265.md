## 変更

1つの EffectProgram に、同じ人の「一時外出」と、それより後の時刻の「帰還」を書くと、計画の段階で拒否されていました（#185）。計画の検査が分岐した時点の状態だけを見て、「帰還の対象はすでに不在の人」でなければならないとしていたためです。

- **計画の検査**（`events/effects.py` の `validate_effect_program`）
  - 帰還の対象が分岐の時点で在所していても、同じプログラムで、それより前の時刻に一時外出させる人なら受け付けます。
  - 帰還だけのプログラムや、帰還が一時外出より前にあるプログラムは、これまでどおり拒否します。メッセージは「…retained absent person or one this program takes out earlier」です。
- **実行時**（`domain/population_lifecycle.py`）：#181 で、一時外出は本人の手が空くまで1分ごとに延期されます。そのため、帰還の時刻までに外出していないことがありえます。この場合の扱いは、相談のうえ「外出を取りやめる」と決めました。
  - 延期中の一時外出は、同じプログラムの帰還の時刻が来たら取りやめます（抑制。「temporary exit dropped: the person was not free before the return in the same EffectProgram」）。帰る予定の時刻（`expected_return_minute`）を過ぎた外出を取りやめる、#181 の扱いと同じ考え方です。
  - 帰還は、本人がまだ外出していなければ行いません（抑制。「return skipped: …」）。これまでは失敗として記録されていました。
  - 同じプログラムの予定は、プログラムの記録（`effect_program_v1` の `scheduled_event_ids`）から、予定中のイベントとイベントログを引いて調べます。保存する項目は増やしていません。
- 係数は変えていません。
- `docs/simulation-models.md` に追記しました。

## テスト

- `tests/integration/test_population_presence.py`（生成Scenario）
  - 帰還だけのプログラムと、帰還が先にあるプログラムは、計画の検査で拒否されること。
  - 10分に一時外出、20分に帰還のプログラムで、履歴が `[(10, temporary_exit), (20, returned)]` になり、本人が在所に戻ること。
  - 支援の要請中で手が空かない人に、10分に一時外出、11分に帰還のプログラムを適用すると、11分に帰還が「return skipped」、延期中の外出が取りやめとして、どちらも抑制で記録されること。そのあと外出もせず、在所したままであること。
  - 修正を戻すと、この2つのテストは失敗します。
