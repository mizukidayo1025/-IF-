## 変更内容

背景のjobの終わりを、実時間の短い期限で状態を読み続けて待っていたテストを、jobの完了そのものを待つ形にしました。`DemoJobManager` も `ProjectAPI` も workerが1つで、worker の中から次のtaskを入れないので、何もしないtaskを入れてその完了を待てば、それより前のjobはすべて終わっています。#143 の案のうち、すでに `tests/integration/test_resume_checkpoint_loads.py` などで使っている **テスト側の形** にしました。製品に待つためのAPIを足す案は、今は製品側に使い道がなく、公開の契約が増えるだけなので見送りました。製品コードは変えていません。

| 場所 | 前 | 後 |
|---|---|---|
| `tests/conftest.py` の `wait_for_job` | 5秒の期限で0.01秒ごとに状態を読む | `manager._executor` の完了を待ってから状態を確かめる（120秒は止まったときのためだけ） |
| `tests/integration/test_demo_live_recompute.py` | 10秒の期限の独自の待ち | `wait_for_job` を使う |
| `tests/integration/test_scenario_editor.py` | 5秒の期限のループ | `wait_for_job` を使う |
| `tests/integration/test_llm_outcomes.py` | 0.1秒×600回のループ | `api._pool.submit(lambda: None).result(timeout=120)` |
| `tests/integration/test_demo_jobs.py` の `Event.wait`（6か所） | 3秒 | 120秒（`HANDSHAKE_SECONDS`）。イベントで待つ形はそのままで、止まったときに抜けるための安全策だけを大きくしました。`entered.wait` は worker が Checkpoint を保存して動き出すまでを待つので、混んだPCで3秒を超えるおそれがありました |

確かめる内容（期待する終わりの状態、その後の確認）は変えていません。`test_demo_live_recompute` の `status == "completed"` の確認は、`wait_for_job(..., {"completed"})` に移りました。

`docs/testing.md` の「テストの置き場所と名前」に、背景のjobの待ち方の決まりを1項目足しました。e2eの300秒の期限（HTTPの外から読むので完了の通知がない）は、#143 のとおり変えていません。
