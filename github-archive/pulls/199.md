## #195：環境の変更の期限切れが「失敗」になる

### 原因

環境の変更の処理（`events/effects.py` の `EffectProgramEnvironmentHandler.apply`）は、`EventApplicationError` だけをそのまま通し、それ以外の `ValueError` を「失敗」（`zone environment modifier is invalid: …`）に包み直していました。

期限切れの処理は、開始が guard で抑制されて修飾がないとき、正しく `EventSuppressed` を投げています。しかし、`EventSuppressed` は `ValueError` の子クラスなので、ここで「失敗」に包み直されていました。

### 変更

`EventSuppressed` も包み直さずに通します。

同じ包み方をしている `try` をすべて洗い出し、中で `EventSuppressed` が出うるのはこの1か所だけと確かめました。guard の判定の呼び出しは、どれも `try` の外にあります。図面の変更の期限切れの抑制も、`try` の外で出ています。

## #196：guard の `eq`・`ne` が数値を型で比べる

### 原因

`_evaluate_guard_node` は、`eq` を「型が同じで値が等しい」で判定していました。そのため、整数の項目と小数の値（`0.0`）が一致しませんでした。

### 変更

両方が数値（整数・小数。真偽値は除く）なら、数として比べます。それ以外は今までどおり型まで比べるので、真偽値（`staff.available`）と数値は一致しません。

| guard（`target.capacity` は1） | 直す前 | 直した後 |
|---|---|---|
| `eq 1` | 真 | 真 |
| `eq 1.0` | 偽 | **真** |
| `ne 1.0` | 真 | **偽** |
| `eq True` | 偽 | 偽 |
| `ne True` | 真 | 真 |
