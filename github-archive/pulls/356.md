## 概要

モデル版の違う Run を閲覧専用にする仕組みを入れました。**版はまだ上げていません**（L11 で 1 回だけ上げます）。結果と world・events・KPI のハッシュは変わりません。

利用者の決定（2026-10-31）：版を上げた後の旧モデルの Run は閲覧のみ可、続き・分岐・送信・介入ははっきりしたエラー、暗黙の読み替えはしない。D2：保存の間の分は、保存した時点に丸めて丸めたことを表示し、新しいモデルで計算し直しません。

詳細は `docs/rust-port/lanes/l9-view-only.md` にあります。

## 変更

1. **版の項目：** `model_signatures` に `engine:model` = "1" と `engine:rng_algorithm` = "sha256-keyed-v1" を記録します（`core/model_version.py`）。L11 は `ENGINE_VERSION` の 1 か所を上げます。この項目のない保存は版 1 として扱います（明示の規則で、fixture でテストしています）。`model_version_status` が `_legacy_queue_migration_required` に代わり、既存の規則を保ちます。
2. **読むだけの読み込み：** `Checkpoint.restore_view`、`_load(view=True)`、`CheckpointArchive.decode_restored(view=True)`、`ProjectStore.load_view_checkpoint`、`checkpoint_model_status`（キャッシュあり）。ハッシュと復元の検査は続けるので、書き換えられた文書は旧モデルではなくハッシュの不一致として出ます。閲覧用の世界には `SavedPointView` の印が付き、`TickEngine`（作成時と `step` ごと）、`OfflineSimulationController`、`BranchRuntime`（作成、`apply`、`apply_effect_program`）、`Checkpoint.capture` が印のある世界を拒否します。
3. **D2 の丸め：** 旧モデルの Run では、`TimelineStore.view_at`、`iter_worlds`、`frame` が、求められた分以前の保存した時点を tick を回さずに見せます。`iter_worlds` は求められた分ごとに 1 つの世界を返し、`requested_minute()` でどの分の答えかが分かります。応答には `model_view` と `saved_point_rounding`（日本語の文）が入り、frame、replay の frame、比較、履歴、`first_divergence` がこれを示します。履歴の行には `exact: false` が付きます。保存の間の分の PDF は、保存した時点を求めます（`pdf_saved_point_required`）。
4. **拒否：** コード `run_model_view_only`、HTTP 409、文「このRunは旧モデル（版 1）で計算されました。今のモデルは版 2 です。閲覧のみです。…」。対象は `advance`、`fork`、`seek` と tick の経路の読み込み（前の復元で持っていた世界を使い回す経路を含む）、`ProjectAPI.submit` と `fork`（スレッドとプロセス、EffectProgram を含み、worker を始める前に確かめます）、`workspace.intervention`、CLI の `resume` と `fork` です。`web/demo.py` の 2 か所は `restore_view` を使います。旧モデルで保存されたデモのジョブは、再起動時に `failed` のままにして分岐を復元しません。
5. **fixture：** `fixtures/saved_runs/engine-v1-small`（約 440 KB、うち `history.sqlite` 320 KB）と、それを作る `scripts/build_saved_run_fixture.py`。h00_small_replay を 90 分にしたもので、main は 0、30、60 分、子は 30 分で分岐して 60 分で保存しています。`6d5662c` のワークツリーで `SHELTERSIM_NATIVE=0` で作ったので、版を記録する前の本物の保存です。今後のコードで作り直してはいけません。テストは版を 2 に見せる `newer_engine` の fixture を使います。版を "0" に見せて計算した Run が今すでに閲覧専用になることも確かめています。
6. **旧方式の移行：** 列の移行は同じ版の Run では従来どおりで、閲覧でも適用します。新しいスイッチ `LEGACY_SHAPES_TICKABLE`（今は True）を False にすると、FIFO の列の方式と情報のスキーマ 1 の保存が閲覧専用になります。L10 が該当の Python の fallback を消すときに False にします。

**計画の訂正：** WorldState v5 は旧形式ではありません。資源サービスのない Scenario では今も書かれます。棚卸しで O（旧形式）としていた `tick_validation.rs:258` は通常の Run で届くので、分類し直しが必要です。

## 変わる動作と既存のテスト

- `checkpoint_hash`、Run の記録の `model_versions`、trace の `policy_versions` に 2 つの項目が入ります。world・events・KPI のハッシュは変わりません。
- 生成した Run の PDF は版の行が長くなって 8 ページになったので、そのテストの上限を 7 から 8 にしました。
- `test_registry` は、版の検査がハッシュの検査より先に動いていたので「explicit migration required」を得ていました（v1 の規則でハッシュを作り直していました）。今は `ViewOnlyRunError` を期待し、ハッシュを正しく計算します。
- `test_checkpoint_cache` は、`_world_document_for_restore` が状態も返すようになったので直しました。
- プロジェクトの比較の `same_models` は、engine の項目がないものを版 1 として扱います。

## 分かっている弱点

- ブラウザーは `.venv` の Playwright で、版を 2 にしたサーバーに対して手で確かめました（`/admin` と `/demo-v2` で注記が出て 30 分に戻り、ページのエラーなし）。自動テストではありません。自動テストは replay player の node のテストだけです。
- `/demo-v2` の計算ボタンは押せるままで、サーバーが断ります。
- **閲覧でも、復元した世界を今の検証で確かめ直します。** L11 や D6 で検証が厳しくなると、旧 Run が閲覧でも開けなくなる恐れがあります（`checkpoint_incompatible_or_corrupt`）。L11 への申し送りとしてレーン文書に書きました。
- 旧モデルの frame は frame のキャッシュに書かないので、閲覧のたびに Checkpoint を復元します。長い Run での遅さは測っていません。
- 版を上げるまで利用者に見える変化がないので、README は変えていません。
