## 元の本文

乱数（`CounterRNG.random`）のキーを、`json.dumps` を使わずに部品ごとに書きます。引く値は変えません。

## 変更

- `CounterRNG.random` は、1回ごとに `json.dumps(list(key_parts), ensure_ascii=False, separators=(",", ":"))` でキーを作っていました。100人・1440分の計算で約77万回呼ばれます。
- 型がちょうど `int` の部品は `str(part)` で、型がちょうど `str` で JSON がそのまま引用符で囲むだけの文字列（制御文字・バックスラッシュ・引用符を含まない文字列）は `'"' + part + '"'` で書きます。どちらも `json.dumps` が書くbyte列と同じです。
- それ以外の文字列や、`str`・`int` のサブクラス（`StrEnum`・`IntEnum` など）は、これまでどおり `json.dumps` で書きます。
- 文字列・整数以外の部品と `bool` は、これまでと同じ `TypeError` で拒否します。
- アルゴリズムの識別子（`sha256-keyed-v1`）、seed の扱い、ハッシュの作り方は変えていません。

## 結果（ローカル、WSL2、1回ずつ）

- マイクロベンチマーク（4つの部品のキーで20万回）: 0.47秒 → 0.27秒
- 100人・生成Scenario・1440分・ProjectAPI経路: tick計算 66.7秒 → 65.3秒。全体は 122.5秒 → 123.8秒で、**全体の差は保存時間の揺れ（±2秒程度）の範囲で、効果ははっきりしません。**
- world・events・metrics のハッシュは develop `bf9cd88` と一致しました。
