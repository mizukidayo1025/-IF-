## 概要

毎 tick の検証を 1 回の kernel にまとめ（`native/src/rules/after_tick.rs`）、`MetricsRecorder.capture` も Rust へ移しました。結果は変わりません。`validate_after_tick` は約 28% 減り、tick は約 4〜7% 短くなりました。tick の差は A/A の揺れと同程度です。

検出が弱くなる狭い場合が 1 つあります（下記）。

詳細は `docs/rust-port/lanes/m6-validate.md` にあります。

## 移した処理

- `rules/after_tick.rs`：比べる対象が動いていない tick で、`begin`、すべての規則、`commit` を 1 回で行います。全部通して記憶を進めるか、記憶に触らず `Unsupported` を返して Python の検査（エラー文つき）が動くかのどちらかです。
- `Plan`：kernel が `model_configs` から読むものを持ちます。検査が通った後で Python が作ります。
- 検証は `_RUST_VALIDATORS` から取ります。validator のない規則は kernel から Python の規則を呼びます。
- `metrics.capture`：driver で `_MetricSink` のとき Rust が行います。
- `_parsed_config`：スコープにある項目は Python を呼ばずに読みます。

`entity_rules` は行ではなくオブジェクトを読むままです。`agent.__dict__` への書き込みが行に届かないので（T のレーンの指摘）、これを安全に置き換える方法は見つかりませんでした。

## 分かっている弱点

- **検出が弱くなる場合が 1 つあります。** Python の体の規則は `population_dynamics_v1` から `historical_ids` を毎 tick 作り直していたので、ハッシュできない ID でエラーを出しました。kernel は名前空間の世代に頼るので、`dict.__setitem__` で木の節点を飛ばしてそのような値を書くと、次の完全検証まで見えません。T のレーンが記録した穴と同じ種類で、`src/` にそのような書き込みはなく、テストもありません。
- **規則の一覧が 2 か所にあります。** `validate` に規則を足すときは `after_tick.rs` にも足す必要があり、足し忘れると kernel はその規則なしで通します。検出できるのはシャドーとテストだけです。`_install_after_tick_kernel` の patch の表も手で管理しています。
- 感度：係数がないので規則を外して 27 通り試しました。26 通りはテストが検出します。残り 1 つ（確認する依頼の順序）は結果を変えないことをコードで確かめました。ハッシュとシャドーはほとんど検出しません。ゲートは正しい状態にしか届かないためです。最初のテストは 9 通りを見逃したので、テストを直して再実行しました。
- 全シャドーのゲートは最初 14 件の差を出しました。このシャドーの探りが壊れたコピーをほかのシャドーへ渡したためで、探りをこのシャドーだけのときに限ると 0 になりました。件数が 0 になることで確認しており、14 件を 1 つずつは追っていません。
- 7 日間は段階ごとに比較していません。負荷が 4 未満での比もありません。内訳は 1 回の cProfile です。
- Rust の行の網羅は測っていません。Linux 以外は CI に任せます。新しい C API は `PyObject_GenericSetAttr`（stable ABI）だけです。

## 残り（Python）

`TickValidationMemo`、`validate`、設定の解析、kernel から呼ぶ `validate_temporary_spaces_state`、`validate_geometry_overlay_state`、`validate_facility_queue_state`、`validate_population_lifecycle_state`、`unsettled_requests`（`added_values` が 1 tick 3 回、約 26 µs。省くと `dict.__setitem__` の書き込みが隠れるので残しました）、`selected_models`（8–9 回 / tick）。kernel が `IdMap` と `TrackedList` の Python の上書きを通す書き込みが約 10 回 / tick（約 10 µs の見積もり）残ります。

## モデル担当の確認事項

係数は移していません。`after_tick.rs` にも持つようになった形の検査は、体の履歴の項目、運用と区域の環境のスキーマ、モデルがないと許されないイベントの種類です。Rust だけの拒否（Python が判断します）：型が完全に一致しない値、世界にいない体の履歴の当事者、運用の状態がない `resource_delivery` イベント、`capture` で分が素の整数でないとき。
