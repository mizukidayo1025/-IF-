## 元の本文

手順3の前段 P5 です。Rust が `psychological_distress_v1` と `metric_state` を持ち、長期の苦痛と苦痛の監視の規則を Rust へ移します。以後の名前空間の雛形です（`docs/rust-port/lanes/p5-template-namespace.md`）。

## 入れたもの
- `native/src/core/row.rs`：`state_row!`（`from_py`、`to_py`、`write_json`、転送された書き込みの処理、写しへの書き込みを1つの宣言から作ります）
- `native/src/state/psychological_distress.rs`、`metric_state.rs`、`native/src/rules/psychology.rs`
- tick で名前空間を丸ごと書く処理はなくなりました
- `benchmarks/rule_shadow`：呼び出しごとに Python の規則と kernel を両方動かし、JSON の文字列で比べる道具

## モデル担当に確認してもらう、移した規則
係数と式の意味は変えていません。使う演算は四則と `py_max`・`py_min` だけで、libm は使いません。
- `update_psychological_state`：毎日の積算と日の終わりの D の式
- `record_distress_monitor_tick`：連続、最長、回数、回復の処理（係数なし）
- `validate_psychological_state`
- Python 側は、ビットを比べるために `next_long_term_distress` を同じ計算のまま切り出しました。Python の規則は比較の基準として残します

- 全経路のゲート：55 Scenario、問題 0。7日分：`--expect` 付きで一致。`ruff`、clippy は通過

- `first_difference --both`：55 Scenario の 220,892 段階がすべて一致。乱数は 14,349 個を比べて差は 0（Rust の中の乱数は比べられません）

## 分かっている制限
- **kernel が静かに動かなくなることがあります：** 最初の版は毎 tick `Unsupported` を返しても、ハッシュはすべて通りました。気づけたのは比較の道具と `whole_writes` のテストのおかげです。レーンでは、kernel が実際に動いた回数の確認を必須にしています。
- ゲートに日の終わりは2回しかありません。日の終わりは 7 日分の比較とランダムなテストで主に確かめています。
- `model_state[KEY]` を持ち続けると、前は写しでしたが、今は後の tick の変更が見えます。`src/` に持ち続ける箇所がないことは検索とテストで確かめただけです。
- 同じ `policy_version` の別の policy は見分けられません。`world.metric_state = {...}` は `__setattr__` で受けず、その世界は以後ずっと Python で動きます（結果は同じで遅くなるだけ）。
- 順序を逆にする試験は Rust の行の中の順序を変えません。ここの規則は ID で並べるので問題ありませんが、後の規則には当てはまりません。
- 追跡ミラーのプラグインの下では `test_first_difference.py` の 4 件が失敗します。P4 の時点でも失敗していて、この PR の変更が原因ではありません。原因は調べていません。
