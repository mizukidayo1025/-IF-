## 変更

#245 で、`ProjectStore` は最後に読んだ2つの Checkpoint について、復元した世界の複製を持つようになりました。この PR では、どの読み取りにも使われないまま60秒経った複製を捨てます。

- 複製は、変わらない EventLog の記録と予定イベントを元の世界と共有しています。そのため、持っている間は元の世界の記録も残ります。
  - 1440分の世界1つで、読み終わったあとも Python のメモリが約148 MiB 残っていました（複製なしでは約4 MiB）。RSS では 448 MiB と 224 MiB です。
  - これまでは、別の Checkpoint を2つ読むか、サーバーを止めるまで手放しませんでした。
- 複製を持ったときと使ったときに、最後に使った時刻を記録します。タイマー（daemon の `threading.Timer`）が、最後の使用から60秒経ったところで複製をすべて捨てます。その間に使われていれば、残りの時間でタイマーをかけ直します。
- 捨てたあと、`gc.collect()` を1回呼びます。何もしていないサーバーではメモリの割り当てが起きず、回収が自然には走らないためです。1440分の世界の例では、参照を外すと RSS が 450 → 289 MiB、回収のあと 224 MiB になりました。
- 複製の管理は、保存のロック（`_mutex`）とは別のロック（`_restored_lock`）で行います。タイマーが、長い保存を待たないようにするためです。
- 時刻を動かす、比較を繰り返すといった続けて操作している間は、これまでどおり複製を使います。

## 結果（ローカル、WSL2）

1440分の main と、1380分で分岐して1440分まで計算した child の Project で、ProjectAPI 経路で2本の比較（1426分）を1回行いました。計測のため、待つ時間は2秒にしています。

| | RSS |
|---|---|
| 起動直後 | 65 MiB |
| 比較の直後（複製を持っている） | 469 / 468 MiB |
| 3秒後（複製を捨てたあと） | 374 / 377 MiB |

約95 MiB が OS に戻りました。残りは、Python が一度使った領域をすべては OS に返さない分です。複製がなくても残る分で、この PR の対象外です。比較の応答のハッシュは変わりません。

  - 実際のタイマー（待つ時間0.05秒）が複製を捨て、そのあとの読み取りでまた持つこと。
