## 元の本文

## 概要

生成Scenarioの職員が清掃・保守の技能を持たないことを、意図した設計として扱います。そのうえで、清掃・保守などの作業指示（`staff_task_order`）を受けられる職員がいないときは、利用者が次に何をすればよいか分かる理由を、承認前に返すようにしました。

Closes #75

## 方針

- 避難所の清掃は避難者の当番や自治組織が、設備の修理は施設管理者や業者が担うことが多いです。そのため、生成Scenarioの職員には清掃・保守の技能を与えません。
- 修理は、介入の修理の手配（`facility_repair`）で表します。
- シミュレーションの結果は変わりません（`generated_small` の固定hashもそのままです）。

## 変更

`validate_staff_operation_order` の技能の確認で、英語の内部エラー（`staff task order worker lacks the registered task skill`）の代わりに、次の理由を返します。形は、PDF分析などと同じ「コード: 日本語の説明」です。画面（demo-v2）は検証エラーをそのまま表示します。

| 状況 | 理由の例 |
|---|---|
| 誰もその技能を持たない | `no_qualified_staff: 清掃の技能（cleaning・sanitation）を持つ職員がいません。担当変更（set_staff_role）で職員に技能を与えてから指示してください。` |
| 誰も保守の技能を持たない | 上に加えて「設備の修理は修理の手配（facility_repair）で指示するか、…」と案内します |
| ほかの職員なら技能を持つ | `staff_lacks_task_skill: staff_002は巡回の技能（patrol・support）を持ちません。技能を持つ職員（staff_001）に指示してください。` |

情報提供・受付・巡回の指示も、同じ確認を通ります。
