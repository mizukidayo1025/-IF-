## 元の本文

容量の確認の一貫性を変える PR です。#47 で「保存のたびのディスクの走査を減らさない」と決めた点を変えます。判断と影響の見積もりは #237 に書きました。

## 変更

- Checkpoint の保存（`ProjectStore._save_branch`、プロセス間のロック `transaction()` の中）では、容量を確かめるたびに（1回の保存で5回）ストア全体を数え直していました。
- 保存の最初に1回だけディスクを数え、それ以降の確認では、その値に、この保存が書いた分を足して使います。
  - JSONファイルの書き込み: 増えたbyte数とファイル数
  - 新しい chunk: byte数とファイル数
  - 消した書き込み中の印: 減ったbyte数
- 保存の途中で、別のプロセスやロックを取らない書き込み（frame のキャッシュ、history index など）が書いた分は、次の測定から数えます。**ここが、#47 の一貫性から変わる点です。**
- 保存の外の容量の確認（history index、frame、画面の使用量の表示）は、これまでどおり毎回数え直します。
