## 元の本文

移植の各系統が衝突せずに追加できる Rust の基盤を入れます。動作は変わりません。

## 変更
- `native/build.rs`: `src/state/*.rs` と `src/rules/*.rs` を走査します。系統は `lib.rs` を編集せず、`sheltersim_native.rules.<name>`、`.state.<name>` として現れます（Python からは `native.rules()`、`native.state()`）。
- `native/src/core/`: `value`、`mathx`、`rng`、`interner`。
- `native/clippy.toml`: `mathx` の外での `f64::{exp, exp_m1, powf, hypot, max, min, powi, clamp, round}` と、swap 系の削除を禁じます。
- crate の追加（`indexmap`、`smallvec`、`rustc-hash`、`itoa`）。心理と接触の kernel を `mathx`、`rng` に移行しました。

## 境界コストの計測（**中止の基準に触れました**）
19 の名前空間すべてを Python のミラーで追跡すると、tick は +18%〜+36% で、基準の +25% に触れます。全部を単純に転送すると 1.7〜4.9 倍です。ただし、この数字は全部を一度にミラーした最悪の場合です。
- 1 項目の書き込みの転送: 0.12〜1.3 µs（基準 3 µs 以内）
- 名前空間まるごとの書き込み: `resource_ledger_v1` は約 60 ms（`domain/resources.py:642`）

**設計の変更:** まるごとの書き込みは転送せず、そのコードを名前空間と同じ PR で移します。ミラーは移した名前空間だけにして、系統ごとに tick の予算（並走で +10% 以内）を確かめます。数字の全体は `docs/rust-port/lanes/p3-skeleton.md` にあります。

## 浮動小数の罠（`mathx` の理由）
- `powf(x, 2.0)` は `mulsd` にコンパイルされ、`x ** 2` と 100 万件中 790 件で違います。`powf(x, 0.5)` も `sqrtsd` になり 865 件で違います。
- `pow(black_box(x), black_box(y))` は実際に libm を呼び、違いは 0 件です。`mathx` はこれを使います。
- CPython が例外を出す場合などは `None` を返して Python に任せます。

`psychology::step` は、`math.exp` が例外を出す入力で `None` を返すようにしました（前はこの無限大を 1.0 に丸める可能性がありました）。7 日分のハッシュは変わりません。
