## 元の本文

各保存の完全検証で、前回通った履歴の項目を読み直さないようにします。1 回の検証は、負荷のある 7 日目の世界で約 130 ms から 12〜20 ms（加えて比較に約 12 ms）になります。変わった古い項目は、**同じ保存で**見つかります。Run の終わりまで待つ読み取りはありません。

## 作り（`core/save_validation.py`）
- 保存の前に、各履歴を前回の保存の文書と比べます（`native/src/history.rs` の `same_json_items`）。`==` より厳しく、`1`・`1.0`・`True`、タプルとリスト、`0.0` と `-0.0` を区別します。
- 飛ばすのは、完全に一致する先頭の項目だけです。違いがあれば、同じ保存でその履歴を全部読み直し、規則が今までどおり判定します。
- ほかの状態（支援依頼、設定、関係など）は、これまでどおり毎回の保存で読みます。tick の検証で「次の完全な検証まで見つからない」としていた種類も、ここで見つかります。
- 復元した世界は新しいキャッシュになるので、最初の検証は完全です。失敗した capture は memo を捨てます。Rust がなければ memo はありません。
