## 元の本文

## 概要

WorldState v6 の毎 tick の検証を、最初の tick も含めて Rust で行うようにしました。記憶（`TickMemo`）も Rust に持ちます。`TickValidationMemo`、`_steady_plan`、`begin`、`commit`、`requests_to_check`、Python の `unsettled_requests` を消しました。ハッシュは変わらず、新しい係数はありません。

詳細は `docs/rust-port/lanes/l7-validate.md` にあります。

## 設計

- kernel が tick を拒否したときは、Python が記憶なしで `validate(validate_event_history=False)` を実行します。`SHELTERSIM_NATIVE=0` と同じ規則とエラー文です。
- 設定は変わったときだけ読みます（記憶の最初の tick か、`model_configs` への書き込み）。読むのは `core/tick_validation.py` の `tick_plan`、`body_config_ids` で、契約（pydantic、`canonical_*`）を使います。これは D3 で Python に残すもので、tick の経路に残る唯一の Python の呼び出しです。設定が変わったときだけ起きます。
- 実体の規則と、仕事中の職員の規則は行ではなくオブジェクトを読みます（T のレーンの指摘のまま）。

## 移した規則

presence の台帳の検証、ライフサイクルの状態（登録した validator。保留の移動の確認はタスクのオブジェクトを読みます）、仕事中の職員のいる `staff_operations_v1` の記録（タスク、職員、辺、保留のイベント）、直近の職員の運用の受領と保持中の完了、人の変更、インフラの tick の確認、区域の環境の基準の区域、体の設定の過去の住人と履歴の当事者、区域の容量。受領は、それを追記する kernel が確かめた時点（`record_other` を含む）か、履歴を全部再生した後に、確認済みの印を付けます。

残る拒否は v5 の世界だけです。旧モデルを tick の経路から外すのは L9 です。

## 感度

移した規則を 1 つずつ外して、このレーンのテストを実行しました。presence（3 つ）、`busy_until`、職員の受領の完了、インフラの基本単位、環境の基準、区域の容量は最初から検出します。仕事の期限の規則と体の設定の過去の住人の規則はテストを足して検出するようにしました。「人が変わったら依頼を全部読み直す」はどのテストも検出しません。presence のコマンドは毎回世界を作り直して依頼のオブジェクトも変わり、もう一方の読み直しの条件が全部を読むためです。ゲートのシャドーは人の変更の tick 28 回で Python の規則が通ることを確かめました。

## 分かっている弱点

- 7 日間に仕事中の職員のいる世界はなく、その規則はゲート（265 回）とテストだけです。
- 同じ値の設定を書くと 1 回解析し直すようになりました（以前は等しいと比べて省いていました）。結果は同じです。
- Python の資源の台帳の規則は記憶の予約 ID の近道を失いました。kernel が拒否したときだけ動きます。
- 行の網羅は測っていません。Linux 以外は CI に任せます。新しい C API はありません。
