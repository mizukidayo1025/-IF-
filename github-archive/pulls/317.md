## 元の本文

手順3の前段 P6 です。人・ニーズ・施設・職員・支援の依頼・タスクの状態を Rust の行に持たせ、コンテナを `IdMap(dict)` にします。

## 設計からの変更
**実体を PyO3 の窓口にせず、dataclass のまま `__dict__` を行の写しにして、書き込みだけを転送します。** 計算上は窓口でも予算に収まる見込み（1 tick に 0.2〜0.4 ms、実際の tick では未計測）でしたが、次の理由で写しにしました。

| 読み取り | dataclass | 窓口 |
|---|---:|---:|
| str | 8.3 ns | 20.6 ns |
| enum | 9.0 ns | 21.0 ns |
| float | 8.9 ns | 23.1 ns |
| `agent.needs.hunger` | 10.5 ns | 43.6 ns |

- Python の読み取りが遅くなりません。
- 行に入らない値を実体がそのまま持つので、エラーの文とバイト列が変わりません。
- `__post_init__`、`__eq__`、`repr`、`pickle` を `SHELTERSIM_NATIVE=0` 側と二重に持たずに済みます。
- Rust の規則は行を直接読めます（`entities_of(world)`、`EntityStore::with_rows`）。代わりに Rust からの書き込みは `PyObject_GenericSetAttr` が1回増えます。

## 分かっている制限
- **別名：** `ids = []; facility.queue_agent_ids = ids; ids.append(x)` は、代入でリストを写すので `ids` への追記が届きません。素の dict とは違う動きです。`src` にこうした属性の代入がないことは検索で確かめました。
- **行に届かない書き込み：** `vars(agent)[k] = v` と `profile.provenance` の中身の直接の書き込み。`src` にはありませんが、lint では見ていません。`object.__setattr__` は新しい lint が見ます。
- soak は tick の終わりだけを比べていて、tick の途中のずれは見ていません。soak のフックはこの PR に含めていません。
- `SupportRequestState` を Rust から書くときは `_write_listener` に自分で知らせる必要があります。
- `refit` はまだ誰も呼ばないので、taint した世界は `from_dict` まで taint のままです。行に `write_json` はまだありません。
- `ActiveTask` の生成が 434 ns から 1,808 ns になりました（1 tick に約 2.4 個）。メモリの増加は未計測です。
- Windows と macOS はこの PR の CI が初めての実行です。

## 別の修正
Windows の CI で、保存先のロックを約10秒待った worker が `OSError: [Errno 36]` で起動に失敗しました（`test_a_branch_forks_and_cancels_while_another_branch_computes`）。`msvcrt.locking` の `LK_LOCK` は10回の試行であきらめるためです。`flock` と同じく待ち続けるようにし、テストを足しました。
