## 元の本文

## 概要

5倍高速化の手順の A8 の1つ目です。記録（trace）を出さない tick では、心理の更新で、人ごとの記録を組み立てないようにします。結果は変わりません（ビット単位で同じ）。

生成 Scenario が使う心理のモデル（`IntegratedDistressLifeStatePolicy`）は、3つの段（`SimplePsychologyPolicy` → `LifeStatePsychologyPolicy` → 平均回帰）を重ねて計算します。これまでは、記録を出さないときも、各段で人ごとの trace のオブジェクトを作り、`dataclasses.replace` で何度も作り直していました（1日で約88万回）。最後の段は、その trace の値を使って計算していました。

## 変更

- **`IntegratedDistressLifeStatePolicy.deltas_without_traces`（`policies/psychology.py`）：** 3つの段の式を、そのままの順序で1回のループにまとめました。trace と途中の `AgentStateDelta` を作らず、最後の値だけを作ります。
- **`LifeStatePsychologyPolicy._stress_feedback`：** 体調の式（`body_formula`）があればそれを、なければ組み込みの式を使って、ストレスへのはね返りを返します。`explain_update` と新しい経路の両方がこれを使うので、式は1か所だけにあります。
- **実行器（`experiments/runner.py`）：** trace level が `off` のときだけ、新しい経路を使います。記録を出すときは、今までどおり `explain_update` を使います。
- **変えないもの：** 数式・係数・丸め・tick の順序・乱数。ほかの心理のモデル（`SimplePsychologyPolicy` など）は、今までどおり `explain_update` を使います。

## モデル担当の方へ

モデルのコードに触れていますが、式も計算の順序も変えていません。記録の組み立てを外しただけです。同じ値になることを、テストで毎 tick 確かめています（下記）。
