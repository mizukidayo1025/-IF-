## 元の本文

計算の再開と分岐で、最初の保存が EventLog 全体を変換し直さないようにします。

## 修正前

#44（PR #219）の履歴キャッシュは、継続計算の中で2回目以降の保存にだけ効きます。次の2つの保存は、キャッシュが空のため、EventLog 全体の変換・ハッシュ用のbyte列の作成・復元検証での解析をやり直していました。EventLog は履歴の大半（1440分時点で約46MB）を占めます。

- 再開した計算の最初の保存
- 分岐した子branchの保存

## 変更

- `CheckpointHistoryCache.seed_events(records, documents)` を追加しました。Checkpoint の `event_log` の文書と、そこから復元した記録を、キャッシュの初期値にします。
- 復元した記録は、文書が記録とちょうど同じフィールドを持つとき、元の文書に変換し直したものと一致します。値は、凍結した payload を戻すと同じJSONになり、整数・文字列・列挙値はそのまま往復します。
- そこで、すべての文書のフィールドの集合（記録とイベントの両方）を確かめ、一致しない文書があれば初期値に使いません。古い形式の文書に余分なフィールドや省略されたフィールドがある場合は、これまでどおり全体を変換します。
- `TimelineStore._advance_locked` は、読み込んだ head の EventLog で、`TimelineStore.fork` は子branchを作った Checkpoint の EventLog で、それぞれキャッシュの初期値を作ります。
- 体調履歴などの model_state の履歴とKPIの標本は、これまでどおり最初の保存で変換します。
