## 変更

以前は、h00_small_replay にトイレ区画の給水所と配食所を手で足した Scenario（`resource_service_scenario`）で確かめていました。サービス地点も区画内の移動もありませんでした。`resource_service_scenario` は単体の `unit/domain/test_resource_service.py` が使っているので残しています。

| テスト | 以前 | 今 |
|---|---|---|
| 給水（2通り） | 寝室からなら区画間の移動あり、給水所の区画にいれば移動なし | 寝室からは、通路を通って `food` 区画へ歩き、区画内でサービス地点まで歩く。給水所の区画に置いた場合（`place_three_at_facility`）は、区画間の移動はなく、区画内の移動だけがある。どちらも、`water_service` の技能を持つ職員が対応し、予約から完了までが `service_minutes` であることを確かめる |
| 配食 | 食事の残数・空腹度を固定値（`0.456` など）で確かめる | 給水と同じく、`meal_service` の技能を持つ職員が対応したことを確かめる。空腹度は下の式で確かめる。提供量と残数は Scenario の `resource_service` の設定値から求める |
| trace level | off と summary の出力が同じ | 同じ確かめ方のまま、生成Scenarioで行う |
| `docs/testing.md` | — | 地図の「Scenario」欄を「生成」に直し、#137の進み具合を書き足す |

### 期待値の決め方

ニーズの下がり方は、固定値ではなく次の式で確かめます。

> A001 の値 = 初めの値 − 設定の relief + （何もしない A002 の同じ時間の増え方）

係数そのものを書かないので、モデルの係数が変わっても、提供による軽減の仕組みだけを確かめられます。実行は14分で止めます（A001 の次の判断が15分なので、提供は1回だけになる）。

テストの件数は4件のままです。parametrize の id は `from_sleeping_area`・`in_station_area` に変わります。
