## 元の本文

手順3の前段 P4 です。Rust が状態を持つための土台（`WorldCore`、本番用の追跡ミラー、レーンの登録表）を入れます。**この PR では名前空間を1つも所有しません**。

## 入れたもの
- `core/state_mirror.py`：`TrackedDict`、`TrackedList`、`NamespaceTable`、detach、`OWNED_NAMESPACES`、検証の登録表
- `native/src/core/world_core.rs`、`tracked.rs`、見本の `native/src/state/sample_namespace.rs`
- `experiments/phases/segments.py`：Rust と Python の処理の並びの登録表
- 厳密な型だけを受けていた kernel が追跡の型も読むように変更。`Encoder` と `V::from_py` はそれ以外の継承クラスを拒みます（`Counter` などは `json` に戻り、同じバイト列のまま遅くなるだけです）
- `benchmarks/tick_budget.py`（レーンごとの tick の予算の確認）、手引き `docs/rust-port/lanes/p4-world-core.md`

## 分かっている制限
- **規則を移さず所有すると遅くなります：** 3つの名前空間を所有するだけの試験で +17%（A/A 1.024）。レーンの予算 +10% を超えます。転送で説明できるのは約3%で、残りの原因は特定していません。レーンは規則と一緒に移します。
- ノードの置き場所は1つです。すでに木にあるノードを別の場所へ入れると写しになります（素の dict なら別名になります）。
- `world.__dict__["model_state"]` だけを差し替えると `_core` とずれます（`src/` にこの書き方はありません）。
- detach の前に残っていたノードは、書き込みはエラーですが、読み出しは古い値を静かに返します。detach は見本でしか試していません。
- 検証を省く登録は、kernel が `with_row` で読むことを前提にしていて、`rust_validated` 自体は taint を見ません。
- リストの要素のノードへの書き込みはリストの長さに比例します。
- 所有した名前空間を worker プロセスで動かすテストはまだありません。Windows と macOS はこの PR の CI が初めての実行です。
- `tests/integration/test_first_difference.py` は追跡ミラーのプラグインの下で5件失敗します（4件はベースでも同じ失敗。1件は単独では通ります）。通常のテストでは通っており、この PR では変更していません。
