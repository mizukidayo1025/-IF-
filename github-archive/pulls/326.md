## 概要
毎 tick の検証のうち、Rust の行が持つ名前空間について、古い確認を3つやめます（`psychological_agents_valid`、`information_contacts_valid`、`unit_values_valid`）。どれも kernel が断った後に Python の規則の中で動いていたもので、普段の tick では動いていません。**毎 tick の検証は速くなっていません**（7日分のスレッド CPU：基準 16.17 秒、レーン 16.19 秒）。時間の大半は、まだ Rust が持っていない状態の検証です。`watch.rs` はやめられませんでした（M3 まで必要です）。詳細は `docs/rust-port/lanes/t-tick-validation.md` にあります。

## 直した不具合（M1 の中で入っていたもの）
- **検証の見落とし：** `world.__dict__["model_state"] = ...`、`dict.__setitem__(world.model_state, ...)`、`dict.pop(world.model_state, ...)` の後、kernel が古い行を読んで検査を通していました。世界が行の木を今も持っているかを確かめ、違えば Python の規則を動かします。
- **保存で値が失われる：** 同じ差し替えの後、`capture` が古い行の byte 列を書いていました。再現テストで確認しました（世界の `long_term_distress` は 0.123、保存は 0.0。`dict.pop(world.support_requests, key)` の後は 21件のはずが 22件）。同じ確認を通し、違えば Python のオブジェクトを符号化します。費用は1回の保存で約 1.7 µs です。

`src/` にこれらの書き方はありません。

## 確認（`2c462d8`、Linux）
- テスト：Rust あり 3,052件通過・6件 skip、`SHELTERSIM_NATIVE=0` 2,002件通過・1,056件 skip
- `gate_all_paths.py --expect`、`--reversed-order`：55個すべて問題0件
- 7日分：`--expect` で一致
- `rule_shadow`（ゲート）：保存 217回、差0件。毎 tick の受理 31,667 / 32,201 / 35,061回、差0件、壊した状態を入れた確認 308回はすべて断りました
- ruff、clippy：通過

マージ前（`e26014b`）：`tick_budget.py` 比 0.932、A/A 1.056（雑音の範囲で、速くなったとは言えません）、`tracked_mirror_gate.py` 220行、問題0件。マージ後のミラーゲートは、次のまとめの回で動かします。

## 残っている穴
どれも `src/` にその書き方はありません。
- `agent.__dict__["stress"] = ...`（正しい範囲の値）は行に届かず、保存に古い値が残り、完全検証も復元の確認も通ります。テストが今の動作を固定しています。閉じるには保存のたびに全実体を読む必要があるので、見送りました。
- `dict.__setitem__(world.support_requests, key, other)` は長さが変わらないので見えません（コードを読んだ結論で、動かしていません）。
- `dict.__setitem__` で木のノードに直接書くと、行にも完全検証にも見えません。テストが固定しています（P5 からあります）。
