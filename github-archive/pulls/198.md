## 元の本文

Closes #194
Refs #178

図面の変更の介入（施設の移動、間仕切りなど）に guard を付けると、計画の検査は通るのに、実行時に「guardの対象がない」で失敗し、承認した変更が行われない不具合を直します。係数は変えていません。

## 原因

guard の評価（`events/effects.py` の `_evaluate_guard_node`）は、比べる対象（施設・区画）を、イベントの payload の `facility_id`・`staff_id`・`zone_id`・`resource_id` から探していました。図面の変更の操作は、対象を `target_id` という名前で持っています。そのため、対象が見つかりませんでした。

guard が真でも偽でも同じく失敗していました（偽なら「抑制」になるはずのところ）。

## 変更

対象を探す名前に `target_id` を足しました（最後に探す）。

payload の一番上に `target_id` を持つのは、図面の変更の操作（`schedule_effect_program` の `GEOMETRY_OPERATORS` の分岐）だけです。そのため、ほかの操作の guard の評価は変わりません（コードを確かめた。断水の `target_id` は運営の状態の中にあり、payload ではない）。

## 確かめた結果

生成Scenarioの10分で分岐し、次を試しました。

| 効果 | guard | 直す前 | 直した後 |
|---|---|---|---|
| `move_facility`（`medical_desk`） | `target.working_units eq 1`（真） | failed | applied |
| `move_facility` | `target.working_units eq 99`（偽） | failed | suppressed |
| `set_partition`（`medical`、10〜40分） | `zone.occupancy gte 0`（真） | failed | applied |
| `set_partition` | `zone.occupancy gt 100000`（偽） | failed | 開始も期限切れも suppressed |
