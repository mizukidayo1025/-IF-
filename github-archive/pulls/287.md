## 元の本文

## 概要

5倍高速化の手順の A7（デモの体感）の1つ目です。保存済みの時刻（30分ごと）で分岐するとき、読み込んだ Checkpoint をそのまま子 Branch に使い、作り直さないようにします。

これまでの分岐は、次の順で処理していました。

1. 親の Checkpoint を読み込んで、世界を復元する（`seek`）
2. その世界をもう一度丸ごと Checkpoint にして（検証・文書化・ハッシュ）、子のために復元し直す（`fork_with_checkpoint`）

保存済みの時刻なら、2で作る Checkpoint は1で読んだものと同じです。7日目近くでは、2だけで約38秒かかっていました。

## 変更（`experiments/timeline.py` の `TimelineStore.fork`）

- 次の2つがどちらも成り立つとき、子は読み込んだ Checkpoint と親の世界を、そのまま受け取ります。
  - 分岐の時刻が、読み込んだ Checkpoint の時刻と同じ（復元のあと計算を進めていない）
  - 親の runtime の状態（Branch の系譜・受け付けた操作を含む）が、Checkpoint のものと同じ
- 親の世界は分岐のためだけに読み込んだもので、ほかでは使いません。
- 保存済みの時刻でない場合（間を再計算した場合）は、今までどおり作り直します。

- 残りの大部分は、子 Branch に親の索引の行を写す処理（約55〜70秒）と、親の Checkpoint の読み込みです。
- 索引の行を写すと、7日分の Run では分岐のたびに容量が約3.5 GB 増えます。2回目の分岐で、既定の容量上限（10 GB）を超えて失敗します。これは #256 の「系譜をたどって読む」形で直す予定です。
