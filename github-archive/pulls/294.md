## 概要

#288 の直しです。分岐が子 Branch の保存の途中（索引への登録）で失敗したとき、子 Branch の pointer を残さないようにします。

分岐の保存（`TimelineStore.record`）は、子の Checkpoint と pointer（`branch.json`）を保存してから、索引に登録します。これまでは登録で失敗すると、pointer だけが残っていました。その結果、次の状態になっていました。

- Branch の一覧には子が出るのに、索引にその Branch の行がない
- 同じ子 ID で分岐し直すと、`child branch already exists` で断られる

## 変更

- **`ProjectStore.forget_unindexed_branch`：** 新しい子 Branch の pointer と状態（`status.json`）を消します。Checkpoint の chunk と目録は、内容で名前が決まっていてほかと共有するので、残します。
- **`TimelineStore.fork`：** 子の保存で例外が起きたら、その子の pointer を消してから、元の例外を伝えます。子が新しいこと（同じ ID の Branch がないこと）は、分岐の最初に確かめています。

#290 で、分岐のたびに索引の行を写すことがなくなったので、#288 で起きた「容量の上限を超える」原因はほぼなくなりました。それでも、ディスクの不足などで登録は失敗しうるので、後始末を入れます。

## テスト

- `tests/integration/test_branch_forks.py` に1つ足しました。子の索引への登録をわざと失敗させると、分岐が誤りになり、Branch の一覧に子が残らないこと。そのあと同じ ID で分岐し直せることを確かめます。変更の前のコードでは失敗することも確かめました。
