## 元の本文

Windows と macOS でも CI でテストを流す準備（#48 の段階3で Windows を対応環境に含めるため）で見つかった、Windows でのプロセスとファイルの扱いの不具合を直します。

## 変更
- **プロセスの確認**（`storage/usage.py`）
  - LLM の利用記録で、実行中だった呼び出しのプロセスが生きているかを `os.kill(pid, 0)` で確かめていました。Windows ではシグナル0が `CTRL_C_EVENT` と同じ値なので、同じコンソールのすべてのプロセスに Ctrl+C を送ってしまいます。CI では、テストの実行全体が途中で止まりました。
  - 新しい `process_exists()` は、Windows ではプロセスの終了コードを OS に問い合わせます（`OpenProcess`・`GetExitCodeProcess`）。POSIX ではこれまでどおり `os.kill` を使います。
- **Run の削除**（`ProjectStore.delete_run`）：書き込み権のロックファイルを開いたまま、Run のフォルダーを消していました。Windows では開いているファイルを消せないので、Run の削除が失敗していました。ロックファイルだけは、ロックを手放してから消します。`run.json` がなくなった Run は、その間にほかから取られることはありません。
- **ファイルの共有**（`storage/projects.py`、`storage/frames.py`）
  - Windows では、置き換え中のファイルを開けず、ほかのハンドルが開いているファイルを置き換えることもできません。どちらも一瞬で解けます。
  - 計算中に状態を読む HTTP の要求が保存と重なって、500 を返していました（CI の e2e テスト）。
  - Windows に限り、保存した JSON の読み込みと、保存・frame のキャッシュの置き換えを、最大0.5秒まで試し直します（`retry_while_shared`）。
- **配信するファイルの Content-Type**（`web/server.py`）：`mimetypes` は OS から種類を読みます。Windows のレジストリは JavaScript を `application/javascript` とするので、OS によって応答が変わっていました。アプリのファイルの種類は表で固定し、それ以外だけ `mimetypes` に任せます。
- **Run のピークメモリ**（`web/projects.py`）：Windows には `resource` モジュールがないので、別プロセスの計算で Run のピークRSS を記録できていませんでした。Windows では、プロセスのピークのワーキングセットを読みます（`GetProcessMemoryInfo`）。
- **テスト**（`tests/unit/storage/test_projects.py`）：「容量を数えている間に消えたファイルを数えない」テストは、Windows では飛ばします。Windows はフォルダーの一覧を取った時点の大きさを使うので、消えたファイルも数えるためです。理由はテストに書いてあります。

## テスト
- `tests/unit/storage/test_usage.py`：`process_exists` が、自分のプロセスを生きている、終わった子プロセスを生きていないと判断すること。
- `tests/unit/storage/test_projects.py`：Windows（`os.name` を差し替え）で、一時的に共有されているファイルを試し直し、ずっと共有されていれば例外を返すこと。
- 手元（Linux）の offline 全体テスト：develop `4a3c553` の上で 1342 passed、4 skipped です。`ruff check` と `ruff format --check` も通っています。
- この PR、「文字コード」の PR、「Anthropic の SDK の読み込み」の PR を合わせたブランチで、3つの OS の CI を手動で流し、すべて通りました（[実行](https://github.com/jphacks/tkb_2615/actions/runs/40946318057)）。Windows 固有の部分は、この CI でだけ確かめています。
