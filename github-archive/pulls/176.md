## 元の本文

テストの網羅率（行と分岐）を測れるようにし、2026-10-28時点の値と、テストが通っていない利用者の経路を `docs/testing.md` に記録します。コードとテストは変えていません。

## 変更

- `pyproject.toml`
  - 開発依存に `pytest-cov==7.0.0` と `coverage==7.10.7` を足した（ほかの開発依存と同じく版を固定）。
  - `[tool.coverage.run]`（対象は `sheltersim`、分岐も数える）と `[tool.coverage.report]` を足した。
  - `addopts` には入れていないので、通常のpytestは計測しない。
- `docs/testing.md` に「網羅率の計測」の節を足した。
  - 計測のコマンド
  - `long_simulation` の印のテストを外す理由
  - 担当ごとの値
  - 通っていない利用者の経路

計測の結果（`.coverage`、`htmlcov/`）は、もともと `.gitignore` の対象です。

CIの設定は変えていません。ただし、CIは `pip install -e ".[dev]"` で入れるので、CIでも2つのパッケージが入ります。

## 計測の手順を決めた理由

全件で計測すると2時間6分かかりました（通常は約2分40秒）。7日間のテスト1件が52倍遅くなり、約2時間かかったためです。そこで、`long_simulation` の印のテストを外して計測しました。結果は次のとおりで、外して困ることはほとんどありませんでした。

| | 時間 | 行と分岐 |
|---|---:|---:|
| 全件 | 2時間6分 | 73.2% |
| 印のテストを外す | 7分25秒 | 73.1% |

外したことで通らなくなる行は6行だけでした（`events/effects.py` のguardの比較5行、`web/demo.py` の1行）。

## 2026-10-28の値（`e12b7d4`、印のないテスト）

行77.8%、分岐62.4%、合わせて73.1%。低い順に `region` 46.9%、`web` 66.5%、`storage` 67.4% です。担当ごとの表は `docs/testing.md` にあります。

利用者の経路で、通っていない処理が多いもの：
- Project画面のAPI：`web/project_services.py` の `get` は205行中167行が通っていない。`web/project_queries.py` の `first_divergence`・`compare`・`history` も通っていない。
- 避難者の一時外出・帰還・移動・再会（`domain/population_lifecycle.py`）
- イベントの処理：近接接触、移動の完了の一部、職員の不在、施設の復旧、情報の噂・訂正・接触の一部
- EffectProgramの検証で、不正な入力を拒否する分岐（`validate_effect_program` で115行）とguardの評価
- 図面の取り込み（`plan_import.py` 31.6%、`plan_extract.py` 0%）と外部データの接続
