## 元の本文

分岐元の history index の行を子branchに写す PR です。写した行を今のコードの結果とみなすという判断は、#223 に書きました。

## 変更

分岐した子branchの最初の index 登録で、次の行を、分岐元の index から SQLite の中でまとめて写します（`INSERT … SELECT`）。

- 写す行（子branchが持つイベントとKPIの標本から作るもの）:
  - `events`
  - イベント由来の `social`（キー `event:<id>`）
  - `actions` / `care` / `operations`（キー `applied:<id>`、`care:<id>`、`operations:<id>`）
  - `kpis`
- 写した行の `entities` と `tokens`、件数（`generations`）も写します。`put()` は写したキーの行を作り直しません。
- 作り直す行:
  - `dialogue`（登録時点の体調履歴の窓から作るため）
  - model_state の履歴の窓から作る `social`・`staff`・`transitions`
  - 分岐元の index に見つからなかった行

## 判断が要る点

写した行は、分岐元がその行を登録した時点のコードで作られています。同じ Run の途中でアプリを更新した場合など、分岐元の行が古いコードで作られていると、今のコードで最初から作った行とは一致しません（伏せ字の規則を変えた #187・#190 など）。その場合、子branchの index は分岐元の index と同じ内容になります。
