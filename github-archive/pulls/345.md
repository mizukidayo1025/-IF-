## 概要

`geometry_overlay`、仮設の部屋、`facility_queues_v1` の規則を Rust へ移し、`independent` FIFO と仮設の部屋での就寝も kernel で扱うようにしました。結果は変わりません。

**7 日間にはこれらの規則がほぼ現れません。** 部屋も `independent` の列も間取りの変更もないためで、比較の基準はゲートとテストです。

速度のためではなく、手順 4 で Python の規則を消すためのレーンです。

詳細は `docs/rust-port/lanes/m6-overlay.md` にあります。

## 移した処理

- `rules/overlay.rs`：`domain/temporary_spaces.py` の全部。`domain/geometry_overlay.py` からは寝台と部屋の受け入れ、`place_installed_facility`、`validate_geometry_change`、`apply_geometry_change`、状態の検査
- `rules/effects.rs`：これらの規則を名前ではなく直接呼びます。
- `Geo::of`：実効の間取りを自分で作り、サービス地点を持ちます。
- `state/facility_queues.rs`、`rules/facility_queues.rs`：`facility_queues_v1` の型付きの行と規則
- `independent` FIFO：列、移動、サービス、`rules/toilet.rs`、`arrive` の kernel が扱います。
- `apply_effect`：`_apply_effect` の仮設の部屋の枝

## 分かっている弱点

- **1% の係数は、ほぼテストだけが検出します。** 格子の 0.68 だけは `interventions` のハッシュでも見えます。間隔、壁の余裕、格子の増加、部屋の候補の上限の 4 つは最初どれにも検出されなかったので、テストを足しました。
- **検出できないものが 1 つあります。** 列の依頼の上限 100,000→101,000 は、kernel の別の確認（列の依頼が全依頼と一致し 1 人 1 件）があるので、この上限だけが効く状態が作れません。
- **給水と配食の地点の容量 `>=`→`>` はハッシュとシャドーだけが検出し、テストはありません。**
- 操作ごとの実行はゲートで少数です（`move_facility`、`transfer_equipment` は各 1 回）。拒否の枝は決まった例だけで、ランダムな入力はありません。
- `split_queues` に職員が必要な地点があるかは数えていません。職員の予約があるトイレの完了は、テスト 1 件だけの比較かもしれません。
- シャドーを絞ると `sitecustomize` の `IndexError` で 3 つしか読まれないまま、ハッシュは通る事例がありました。出力に 1 行出るだけなので、絞るときは確認が必要です。
- RSS と Rust の行の網羅は測っていません。Linux 以外は CI に任せます。新しい C API はありません。
- `rules/population.rs` は overlay と部屋の状態を自分で読んでいます。手順 4 の前に `rules/overlay.rs` へまとめます。
