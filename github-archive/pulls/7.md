## 背景

## 変更内容

1. **地域検索の出典候補**（`src/sheltersim/llm/provider.py`）
   - 候補を応答本文の引用からしか取っていませんでした。JSONだけを返す応答にはほとんど引用が付きません。
   - web searchが返した検索結果（`web_search_tool_result`）のURLとタイトルも候補にします。許可ドメインに限り、重複を除いて最大25件です。エラー結果は無視します。
2. **レポートの表示**（`src/sheltersim/web/projects.py`）
   - 画面は、状態が`running`から変わった時点で一度だけレポートを取得します。サーバーはレポートを作る前にRunを`completed`にしていました。
   - レポート（または生成できなかった旨）を書き込んでから`completed`にします。
3. **チャットの根拠照合**（`src/sheltersim/web/results_chat.py`）
   - 根拠の値は「JSON形式の値」である必要があり、文字列は引用符付きでなければ不合格でした。Claudeは記録された文字列をそのまま返すため、文字列を引用した根拠は必ず失敗していました。さらに1件の失敗で全factを捨てる作りだったため、正しく引用された数値5件まで捨てられていました。
   - 記録値とまったく同じ文字列であれば、引用符なしでも受け付けます（`_proof_matches`）。丸めた値、型を変えた値、言い換えた文字列は、従来どおり拒否します。
4. **同じ依頼の繰り返し**（`src/sheltersim/llm/accounting.py`、`src/sheltersim/web/workspace.py`）
   - 利用記録は同じ依頼に二度課金しません。しかしWebの下書きプレビューとRunの分析は応答（tape）を保存していなかったため、同じ依頼を繰り返すと重複として拒否され、ruleの結果になっていました。画面では他の項目を直してプレビューし直すことが多く、実際には各下書きの最初のプレビューでしかAIが働いていませんでした。
   - `StoredResponseTape`を追加し、`usage-tapes/<draft>.json`と`runs/<run>/analysis-tape.json`に応答を保存して再利用します。同じ依頼は、APIを呼ばずに保存済みの応答を使います（無料）。
   - 保存するのは応答だけで、promptは保存しません。sanitize後の内容が元と変わる応答（連絡先や秘密情報に見える文字列を含むもの）は、保存せずにその場限りで使います。利用記録の重複拒否の仕組みは変えていません。
