## 概要

5倍高速化の続きです。保存のたびの「復元の確認」（#280）を軽くします。

#280 で、復元の確認は「保存した文書から世界を組み立てて、保存前に検証した世界と同じか比べる」形になりました。その組み立て（`WorldState.from_dict`）に、7日目では1回約0.5秒かかっていました。

- 保存した文書を、2回丸ごと写していました（`_world_document_for_restore` と `from_dict` の中）。
- EventLog（7日目で約27万件）を毎回作り直し、ID・順序番号・時刻・種類の索引をすべて作り直していました。

この確認で作る世界は、比べたら捨てます。

## 変更

- **`Checkpoint._world_document_for_restore(..., borrow=True)` と `WorldState.from_dict(..., _borrow=True)`：** 保存の復元の確認では、保存した文書を写さずに、そのまま使って世界を組み立てます。古い待ち行列の移行が要る Checkpoint は、今までどおり写してから移行します。
- **`CheckpointHistoryCache.restored_log` と `from_dict(..., _restored_log=...)`：**
  - 前の保存の確認で作った EventLog（その世界はもう捨てています）に、増えた記録だけを `EventLog.append` で足して使います。索引もそのまま保たれます。
  - その EventLog が前の確認の記録をちょうど持っているとき（数と最後の記録が同じとき）だけ使い、ほかは今までどおり作ります。
  - 読み込みや分岐で始めたとき（`seed_events`）の記録は、計算中の世界の EventLog のものなので、使い回しません。
- **変えないもの：** 復元の確認の内容（同じ状態かを比べ、違えば完全に検証する）、保存の形式、ハッシュ、計算の結果。
