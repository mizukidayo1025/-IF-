## 元の本文

再生用の frame の一括読み取りで、各 branch の最初の分も、復元元の Checkpoint の EventLog を再利用してハッシュを計算します。PR #240 の続きです。

## 変更

- PR #240 で、再生の分ごとのハッシュを履歴キャッシュで計算するようにしました。ただし、各 branch の最初の分では EventLog 全体を変換していました。1440分時点で約1.7秒かかります。
- `TimelineStore.iter_worlds` に `history_cache` 引数を追加しました。渡されたキャッシュに、再生が復元した Checkpoint の EventLog とその復元結果で初期値を作ります。計算の再開や分岐と同じ方法です（`seed_events`、#231）。
- そのため、`seek` の中身を `_seek` に移し、復元元の Checkpoint も返すようにしました。`seek` の振る舞いは変わりません。
- 再生（`web/replay.py`）はこのキャッシュを使います。
