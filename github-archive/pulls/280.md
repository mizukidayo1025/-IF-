## 概要

5倍高速化（100人・7日分を画面から計算）の2つ目です。

Checkpoint を保存するたびに行う「復元しての確認」で、復元した世界を完全に検証するのをやめます。代わりに、直前に完全検証した元の世界と同じ状態かを比べます。7日目の時点で、完全な検証は1回約0.7秒かかり、保存1回につき2回（保存前と復元後）走っていました。

## 変更

- **復元の確認（`Checkpoint._capture` の履歴キャッシュの経路）：**
  1. 保存した文書から世界を復元します（`WorldState.from_dict(..., _validate=False)`）。
  2. 保存前に完全検証した世界と同じ状態か、`WorldState.same_state` で比べます。
  3. 同じなら、同じ検証を通るので、復元した世界の検証は省きます。違えば、従来どおり復元した世界を完全検証し、通らなければ `CheckpointError` にします。
- **`WorldState.same_state`：**
  - EventLog と待ち行列以外のフィールドは、そのまま `==` で比べます。
  - 待ち行列は、保存と同じ順序（`pending()`）で比べます。
  - EventLog は、前の保存の確認で同じと分かった先頭の記録（`known_equal_events`）を比べ直さず、増えた記録だけを比べます。
- **`CheckpointHistoryCache`：** 復元した EventLog の記録のうち、元の記録と同じと分かっている数（`restored_events_equal`）を覚えます。
  - 違いが見つかった保存の後は 0 に戻すので、次の保存では全体を比べます。
  - 読み込みや分岐で始めたとき（`seed_events`）は、元の記録が復元した記録そのものなので、全部を同じとして扱います。
- **変えないもの：** 保存前の完全検証は、今までどおり保存のたびに行います（これを増えた分だけにするのは、次の PR です）。読み込み時の検証と、計算の区切りの検証も変えません。
