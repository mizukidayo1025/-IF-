## 元の本文

Closes #159

高い苦痛のモニター（`domain/distress_monitor.py` の `record_distress_monitor_tick`）は、イベントの処理で苦痛がしきい値を下回った回復を数えていませんでした。下回った経路によらず数えるように直します。係数は変えていません。数え方だけの変更で、WorldState・乱数・心理状態は変わりません。

## 原因

モニターは、心理の更新の前（イベントの処理の後）と後の値で判定します。直す前は、更新そのものでしきい値をまたいだときだけ連続を閉じていました。職員の支援などで先にしきい値を下回ると、次の更新では前後とも低くなり、連続が開いたまま残りました。後でまたしきい値を超えると、その連続は回復として記録されないまま上書きされていました。

## 変更

連続が開いていて（`run > 0`）、更新の前後どちらかがしきい値未満なら、回復として閉じます。今がしきい値以上なら、そのあと新しい連続を始めます。

| 更新の前 → 後 | 直す前 | 直した後 |
|---|---|---|
| 高 → 高 | 連続を伸ばす | 同じ |
| 高 → 低 | 回復として閉じる | 同じ |
| 低 → 低（イベントで先に下回った）| 連続が残る | 回復として閉じる |
| 低 → 高（イベントで下回り、更新でまた上回った）| 前の連続を記録せずに新しく始める | 前の連続を回復として閉じ、新しく始める |

最後の行は、Issue に書いた場合（低 → 低）と同じ種類の取りこぼしです。下回ったことを更新の前の値で観測しているので、あわせて直しました。
