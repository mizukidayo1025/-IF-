## 変更

### `integration/test_project_intervention_preview.py`：Project画面の preview・apply を3件追加

demo の `test_nl_demo.py`・`test_nl_demo_branching.py` で確かめている振る舞いのうち、Project画面にもあるものを、Project の経路で確かめます。準備は次のとおりです。

- 生成Scenarioの Run を90分まで計算する。
- 画面の時刻スライダーと同じく、Checkpoint のあいだの40分を選ぶ。
- 文は offline のルールで読む（`e2e/test_project_scenario_to_results.py` と同じ「避難スペースに避難者を10人追加」）。

1. `test_project_preview_changes_neither_the_branch_nor_its_history`：preview の前後で、保存した head と、40分の状態の hash が変わらない。
2. `test_project_apply_forks_at_a_past_minute_and_leaves_the_source_unchanged`：次のことを確かめる。
   - 承認すると、計算済みの範囲の途中（40分）から分岐する。
   - 元の head と過去の状態は変わらない。
   - 子 Branch の `fork_origin` が元の状態の hash を指し、`add_evacuees` の予定イベントを持つ。
   - 同じ子 ID でもう一度承認すると "child branch already exists" で拒否され、元は変わらない。
3. `test_project_apply_needs_an_applicable_preview_its_hash_and_approval`：次の場合は分岐しないことを確かめる。
   - 検証で止まる typed EffectProgram（存在しない区画）の preview（`can_apply` が False）
   - 別の hash での承認
   - `approved: false`
   - シミュレーションできない文の preview（そもそも `preview_id` が返らない）

demo のテストにある「元の Branch が変わった後の preview は適用できない」は、置き換えていません。Project の時系列は計算済みの時刻が変わらないので、apply の「source state changed」の検査は、通常の操作では起きない防御です。demo のテストは残しています。

### `integration/test_behavior_policy.py`：Project画面で選んだ行動Policyのテストを追加

`generated_previews(behavior_policy_id="priority-rule-v1")` で、利用者が生成時に優先ルールを選んだ Scenario を作り、次のことを確かめます。

- 人が歩いている30分で Checkpoint を取り、2つに分けて45分進めると、状態・イベント・指標が一致する。
- 判断の記録が、自律性を持つ版（`priority-rule-autonomy-v2-resource-service-v1`）と出典 `ASM-PRIORITY-RULE-BEHAVIOR-V1` になっている。

fixture の版（`priority-rule-v1`）とは違う版を通るので、fixture のテストも残しています。
