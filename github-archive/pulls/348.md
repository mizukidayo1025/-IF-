## 元の本文

## 概要

Rust の道がなかった読むだけの規則（`zone_environment_view` と 8 つの `zone_*` の式、`PersonContext`、`_misinformation_applies`、近接の抽選、`_schedule_information_contact`）を移しました。結果は変わらず、係数も変えていません。ゲートと 7 日間でこのレーンの拒否は 0 です。

詳細は `docs/rust-port/lanes/l5-read-rules.md` にあります。

## 移した処理

- `rules/zone_environment.rs`：`zone_environment_view`、8 つの式、`ScenarioZoneEnvironmentConfig` と `ZoneEnvironmentBaseline` の解析（既定値、旧来の中立値、範囲）
- `rules/person_context.rs`：`PersonContext` の検証の全部（pydantic のゆるい真偽値を含む）、`_fields_of_person`
- `rules/proximity.rs`：`sample` と `_sample_proximity_contacts`（段階と driver の両方）。行から位置を読み、行が taint していれば木から読みます。
- `rules/world_view.rs`：`_misinformation_applies`。計画どおり、契約の `selected_models` は Python のままです。
- `rules/information.rs`：`_schedule_information_contact` を呼ばず、同じ文で同じ順序番号を取ります。
- Python から `_person_entry` と `_misinformation_applies` を消しました（使う箇所がなくなりました）。
- `_sample_proximity_contacts` を `DRIVEN_STEPS` に足しました。

## 何が何で比べられているか

- **ゲートだけ：** midpoint、limiting、quadratic、proportional の式（各 1,440 回）、閾値の不満が 0 より大きい場合と快適帯のストレスが 0 より大きい場合（`interventions`、各 120 回）、ノイズ（180）、需要の modifier（120）
- **7 日間：** 快適帯、linear、threshold、multiplicative の、0 か既定値の側だけ
- **テストだけ：** 契約の既定値（Scenario が全項目を書くため）、範囲、休息の下限 0.1、limiting でのノイズ、近接の木の経路、拒否された接触

## 分かっている弱点

- **単独で選んだシャドーは、`python_path_only` を付けないと driver に素通りされ、ハッシュは通るのに何も記録しません。** このレーンの最初のシャドーで起きました。このレーンのものは直しました。ほかの絞ったシャドーにも同じ恐れがあります。
- pydantic との一致はファジングで示したもので、証明ではありません。
- `DistanceSampledProximityPolicy.sample` のクラスへの patch は kernel に届きません。
- `gate_all_paths.py --coverage` は実行していません。到達はシャドーの数で確かめました。
- Linux 以外は CI に任せます。

## モデル担当の確認事項

新しい係数はありません。Rust にも持つ値の一覧はレーン文書にあります。判断が必要なものは次のとおりです。

1. modifier の `parameters` の整数（`level: 1`）は、検証を通りますが kernel は拒否します。書く Run はありませんが、D6 と同じ問題で、Python を消す前に決める必要があります。
2. セルが i64 に収まらない座標は拒否します。
3. `register_policy` で足した `zone_*` の式は拒否します。
4. 書く Run はありませんが、pydantic が受け入れるものを拒否します：前後に空白のある設定の安定 ID（検証がすでに拒否します）、人の文脈の JSON 以外の Python の型、別の種類の dict。
