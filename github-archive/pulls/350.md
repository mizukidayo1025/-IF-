## 元の本文

## 概要

trace の文書を形を変えずに Rust で作り、trace のある Run と Provider のある Run も kernel と driver を通るようにしました。ファイルはバイトまで同じです。実装は Rust 約 1,200 行で、計画が警告した 10 倍にはなりませんでした。

**ファイルを書く部分（`RunArtifactWriter`）は Python に残します。** ファイル、spool、`_sanitize`、1 時間ごとの集計は storage の外枠にあたり、完了の定義の範囲内と判断しました。Rust は同じ dict を作って `TraceSink` で渡します。

詳細は `docs/rust-port/lanes/l6-trace.md` にあります。

## 移した処理

1. trace の文書：5 つの心理のモデルの `explain_update` の値、`to_dict`、`trace_document`、寄与の一覧、3 つの社会のモデルと情報の接触の trace、判断の文書（`record_decision_document`）。FULL の `TickTrace` は `phase_observer` で driver 上で動きます。
2. Provider：拒否をなくしました。フックは同じ Python で、kernel から同じ箇所で呼びます。LLM のコード、スキーマ、検証は変えていません。スクリプトとテープだけを使い、有料 API は呼んでいません。
3. `tick_probe` は常に `phase_observer` を使い、`on_driver` はなくなりました。`reversed_order` は driver を通ります。`reversed_within_phase` は手順を patch するので Python の経路のままです。

| `a Provider can be called` | 1,800 | 0 |

## 分かっている弱点

- ハッシュは trace を見ません。下の 1% の変更でもゲートは問題 0 のままでした。感度：`need_pressure`、`selected_probability`、情報の確率、sparse の `stress_difference` はシャドー、`trace_bytes`、テストが検出します。チャネルの `influence_weight`、DeGroot の寄与は `trace_bytes --models` と社会のテストだけが検出します。
- ゲートのシャドーで trace に届く心理のモデルは 2 つだけで、ほかは `--models` とテストに頼ります。
- trace のある区域のノイズ（`zone_environment`）に届くゲートのシナリオはなく、テスト 1 件だけが確かめます。
- `events_shadow` が列の差を 1,100 件報告します。L5 の実行でも同じ数で、このレーン以前からです。Rust がイベントを外した後で写しの列が古くなると読んでいますが、確認も修正もしていません。**そのシャドーの列の比較は効いていません。**
- 実際の Provider では実行していません。スクリプトとテープだけです。
- Rust の行の網羅は測っていません。Linux 以外は CI に任せます。

## 残り（Python）
