## 何を直したか

### #204 拒否の理由が画面に届かない

- 図面の各操作（`extract`・`review`・`proposal`・`trace`・`reviewed_trace`・`geojson`）の`ValueError`を、`StorageError`に包んで返すようにしました。コードは`plan_<操作>_invalid`で、メッセージは「コード: 理由」です。サーバーは`StorageError`を409の`{"error", "code"}`で返すので、画面（`project-round3.js`）はこの理由をそのまま表示します。
  - 例：`plan_trace_invalid: route 'sleeping_food' crosses closed wall 'partition'`
  - 実装では、`PlanServices.preview`の操作ごとの処理を`_operation_result`に切り出し、呼び出し側で包んでいます。中身の処理は変えていません。
- 契約の検証エラー（`ValidationError`）は、項目の場所と内容だけを返し、入力値は返しません（例：`facilities.0.capacity: Input should be a valid integer, ...`）。5件を超えた分は件数だけを返します。これはIssueに書いた案のとおりです。
- `geometry_revision`も同じ形にしました。前から理由を返していましたが、`ValidationError`の入力値も含んでいました。
- Scenarioのプレビューで図面を指定したときは、Scenarioを作れない理由（例：`sleeping`のZoneがない）を`scenario_plan_invalid`で返します。図面を指定しないプレビューの扱いは変えていません。
- JSONとして読めない図面のアップロードは、`invalid_plan_json`（理由付き）で拒否します。前は一律の400でした。

### #202 理由なしで落ちる7種類

`region/plan_import.py`で、どれも理由付きの`ValueError`になるようにしました（上の変更で、画面には409と理由が届きます）。

- トレース：設備の占有範囲を持つ施設が未知のZoneを指す（`StopIteration`だったもの）
- GeoJSON：数値（`width_m`・`height_m`・`usable_area_m2`・座標）は`_geojson_number`で読み、数値にできないものと有限でないものを拒否します。
- GeoJSON：LineString（経路・壁・開口）の`coordinates`が配列でないものを拒否します（`_geojson_line`）。
- GeoJSON（旧形式の封筒）：`zones`・`zone_edges`・`facilities`・`geometry.zones`・`editable_geometry`の一覧が、オブジェクトの配列でないものを拒否します（`_json_objects`）。
