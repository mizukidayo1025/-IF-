## 概要

5倍高速化の手順の A1（物差しを整える）です。計測器（`benchmarks/investigate_performance.py`）に2つの機能を足します。Python の改善でも、実験用ブランチ（`experiment/rust-native`）の Rust の試作でも、同じ物差しで比べられるようにするためです。

## 変更

- **`--expect 前の result.json`：** world・events・KPI のハッシュを、前の計測と比べます。
  - 結果は `result.json` の `expected_hashes` に記録します。
  - 1つでも違えば、終了コード1で終わります。これまでは、ハッシュを手で見比べていました。
- **`--from-project DIR --fork-minute M`（長い Run の終わりだけを測る）：** 前の `--route project` の計測が残した `projects` から、`main` を M 分で分岐し（介入なし、子 Branch は `late-{M}`）、そこから `--duration` 分だけ計算します。
  - 7日分を測るには約17分かかりますが、7日目の保存と tick だけなら数分で測れます。
  - Scenario は、保存された Run のものを使います。
  - 分岐にかかった時間は `late_window.fork_seconds` に記録します。デモで分岐を押したときの待ち時間の目安にもなります。
- **計算が目標の時刻まで進んだかの確認：** 状態が `completed` かではなく、Branch が目標の時刻まで進んだかで確かめるようにしました（途中から測る場合は `paused` で終わるため）。
- **`result.json` の書き込み：** 文字コードを UTF-8 に固定しました（docs/testing.md の決まり）。

## 確かめたこと

- 120分の Run の90分から30分だけ計算すると、元の Run の120分の時点と同じハッシュになりました（`--expect` で終了コード0）。
- 期間の違う Scenario と比べると、終了コード1で `hashes differ` と出ます。

## テスト

- `tests/integration/test_benchmark.py` に1つ足しました。40分の Run を測り、30分から10分の終わりだけを測ると元と同じハッシュになること、期間の違う計測と比べると終了コード1になることを、計測器を実際に動かして確かめます。
