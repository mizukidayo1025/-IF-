## 元の本文

## 背景

「Claude APIを使ってもofflineと同じ結果しか出ない」という報告を調査しました（30人・1日のScenario）。Claudeの応答がほぼ全件rule fallbackに置き換わっていて、そのことがどこにも表示されないのが問題でした。

- 呼出し上限（既定10回）がminute 0の`support-priority-v1`で使い切られ、残りのtaskはすべて`max_api_calls`でfallbackしていました。
- live応答10件のうち7件が`schema_validation_failed`になりました。
- CLIの利用枠`cli-default`は上限が作成時の値で固定されます。使い切った後の実行では全taskが`shared_allowance_unavailable`になり、結果がofflineと完全に一致していました。
- それなのにmanifestは`llm_usage.failures: 0`のままで、CLIも警告を出していませんでした。

このPRは対応の第1段階として、失敗の**可視化**だけを扱います。上の原因そのものは修正しません（別PRで対応予定）。

## 変更内容

- `src/sheltersim/llm/outcomes.py`（新規）：outcome集計を1つの関数にまとめました。model出力本文は読みません。
  - statusは`not_requested` / `offline_rules` / `all_accepted` / `degraded` / `all_fallback`の5つです。
  - fallbackを理由別・error_kind別・prompt版別に数え、最初のfallbackの`call_index`も返します。
- Run manifestの`llm_usage`に`outcomes`を追加しました。中に`summary_schema_version: 1`を持ちます。
  - `failures`は、offline以外のfallbackをすべて数えるよう修正しました。以前は固定リストで判定していたため、`max_api_calls`や`shared_allowance_unavailable`などが漏れていました。
- `sheltersim run`の出力JSONに`llm_status`を追加しました。`degraded`または`all_fallback`のときはstderrに1行の警告を出します。終了codeは0のままです。
- Project route `GET /api/v1/projects/{project}/runs/{run}/branches/{branch}/llm-status`を追加しました（read-only）。head Checkpointに保存済みのrouter記録から読み取り時に集計します。child Branchの値にはfork前に親から引き継いだ記録も含みます。
- 文書：`docs/llm-integration.md`に「fallbackの可視化」の節を追加し、`docs/api-reference.md`も更新しました。

## 契約・互換性

- **永続データ**：manifestに`llm_usage.outcomes`を追加します。`failures`の意味も広がります（漏れていたfallbackも数える）。
  - `artifact_schema_version`は上げていません。`review`コマンドが古いRunの`llm_usage`も書き直すため、版はblock内の`summary_schema_version`で持たせました。
  - `outcomes`がない古いRunの`failures`は、過少な値の可能性があります（文書に記載）。
- **Checkpoint・WorldState**：形式の変更はありません。新しいrouteは保存済みの記録を読むだけです。
- **公開HTTP契約**：GET routeを1つ追加しました。
- 移行は不要です。
