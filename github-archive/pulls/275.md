## 元の本文

Windows と macOS でも CI でテストを流す準備（#48）で見つかった、テストが任意の依存関係に頼っていた問題を直します。

## 変更
- Anthropic の SDK（任意の依存関係 `.[llm]`）を、`AnthropicProvider` を作るときではなく、最初に API を呼ぶときに読み込みます。
  - これまでは、record モードの Router を作った時点で SDK を import していました。そのため、テストや利用記録のアカウントがあとで Provider を差し替える場合でも、SDK が要りました。
  - CI（`.[dev]` だけを入れる）と、文書の手順で環境を作った開発者の手元では、4件のテストが `install the optional LLM dependencies` で失敗していました。
- SDK がない状態で実際に API を呼ぶと、これまでと同じ「`pip install .[llm]` を入れてください」の `LLMProviderError` になります。
  - SDK の読み込みは、API 呼び出しの例外をまとめる `try` の外で行います。そのため、この案内が「Anthropic API request failed」に置き換わることはありません。

## テスト
- `tests/unit/llm/test_provider.py`：SDK を import できない状態でも `AnthropicProvider` を作れて、呼び出すと `pip install .[llm]` の案内になること。
- SDK を入れていない仮想環境で、`tests/unit/llm/test_accounting.py`・`tests/unit/web/test_workspace.py`・`tests/unit/llm/test_provider.py` の56件が通ることを確かめました。
- 手元の offline 全体テスト：develop `4a3c553` の上で 1341 passed、4 skipped です。`ruff check` と `ruff format --check` も通っています。
