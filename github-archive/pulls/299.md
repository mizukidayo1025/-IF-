## 元の本文

tick の終わりの検証を、1 tick あたり約 7 ms から約 1.1 ms にします。`validate()` と `validate(validate_event_history=False)` の規則は変えていません。Run の境界・保存・復元では、これまでどおり全体を検証します。

## 変更
- `WorldState.validate_after_tick` と `core/tick_validation.py`（前回通った事実の memo）。検証に失敗すると memo は捨てます。
- Rust の受理チェック（人、関係、体調、心理、位置、接触など）。普通の値だけを Rust で受理し、それ以外は Python の規則に渡します。エラーを出すのは Python だけです。古い `*_problem` kernel は削除しました。
- `native/src/watch.rs`: CPython の dict watcher で、書き込まれた関係の記録だけを読み直します。

## 省く検査と、省ける理由
| 省く検査 | 省ける理由 |
|---|---|
| 設定の検査 | 設定だけを読む。`model_configs` が保存した写しと等しい間だけ省く |
| 確定した支援依頼 | 自分の項目、Agent ID、「今より後でない」しか読まない。書き込みは `__setattr__` で検知し、ID が変われば全部見直す |
| 在所・ライフサイクル・overlay の状態 | 正規化した JSON と、規則が読む他のものが同じ間だけ省く。時刻や状態に依存する項目があれば省かない |
| 共有の運営の最新の記録 | 記録とその他の項目が同じ間だけ省く。新しい記録は従来どおり検査 |
| `used_reservation_ids` | 新しい ID だけ検査。前の ID は、通ったリストと比べる |
| 関係の記録 | 値は不変で、dict watcher がすべての書き込みを報告する。読み取る `topic_ids` のリストは毎 tick 読む |

各項目について、値を壊して同じエラーになることを `tests/integration/test_tick_validation.py` で確かめています。

## 次の完全な検証まで見つからないもの
- `request.__dict__[...]` や `object.__setattr__` のように属性の代入を通らない書き込み（テストで固定）
- 等しいと判定される設定の書き換え（`1` → `True`）
- 古い共有の運営の記録の書き換え（これは従来と同じ）
- JSON で比べる状態で、リストを等しいタプルに差し替えること
