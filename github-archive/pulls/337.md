## 元の本文

## 概要

毎 tick の指標と、tick の終わりの実体の検証を Rust へ移しました。結果は変わりません。予算の比は 0.915（A/A 1.052）で、負荷の高い状態でしか測れていません。

詳細は `docs/rust-port/lanes/m5-metrics.md` にあります。

## 移した処理

- `rules/metrics.rs`：`snapshot_fields`（`MetricSnapshot.from_world`）、`kpi_values`（`operational_kpi_values`）。どちらも読むだけです。
- `rules/tick_validation.rs`：`entity_rules`（`validate` の実体とイベントの規則を tick の終わりに 1 回の kernel で。可否だけを答え、エラー文は持ちません）、`population_dynamics`（保留の人がいない状態の検証）
- `core/world.py` の規則を `_validate_entity_rules`、`_validate_event_rules`、`_validate_zone_capacity` に分けました。規則とエラー文は Python に残り、保存時と v5 の世界はこれを動かします。
- 区域の環境の設定は、それと区域が変わらない間は tick の記憶で省きます（Python の変更）。

`entity_rules` は実体の行ではなく Python のオブジェクトを読みます。`agent.__dict__[...]` への書き込みを検出するためです。行を読めば速くなりますが検出できなくなるので、オブジェクトを読む形のままにしました。手順 4 でオブジェクトがなくなるときに行へ移します。

`validate_effect_program_state` の kernel は効果が揺れの範囲内だったので外しました。

## 分かっている弱点

- **検証の規則を外しても、シャドーとハッシュは気づきません。** ゲートが正しい状態しか作らないためで、壊れた状態のテストだけが検出します。規則を 1 つずつ外したのは `entity_rules` の 3 つと人口の 1 つだけです。37 種類の破壊と 400 回のランダムな書き込みで裏づけていますが、Python のすべての枝に届くとは示せていません。
- `kpi_values` は行を読むので、`agent.__dict__` への書き込みはその分の KPI に古い値で出ます。`src/` にそのような書き込みはありません。
- 負荷 13 未満での予算の測定はありません。
- 7 日間の全シャドーは実行していません。
- `shadow_staff.py` が `tick_probe.py` のラッパーで `__wrapped__` を見つけられず、全シャドーの `--reversed-order` が落ちていたので、ここで直しました。`generated_project` で落ちなくなり差も 0 でしたが、私が設定した 300 秒の制限で完走前に止まりました。全シナリオでは実行していません。
- Linux 以外は CI に任せます。
