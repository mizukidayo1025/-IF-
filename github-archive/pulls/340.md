## 元の本文

## 概要

人口、仮設の部屋、`geometry_overlay_v1`、`model_configs` の文書を Rust で持ち、書き込みのたびに変わるカウンターで毎分の比較を省きました。結果は変わりません。

**規則は移していません。** `domain/population.py`、`population_lifecycle.py`、`temporary_spaces.py`、`geometry_overlay.py` の書き手は 7 日間で 0 回、ゲートでも最大 161 回です。手順 4 の前に移す必要があります。

詳細は `docs/rust-port/lanes/m6-population.md` にあります。

## 変更

- Rust が持つ名前空間：`population_presence_v1`、`population_lifecycle_v1`、`population_dynamics_v1`、`temporary_spaces_v1`、`geometry_overlay_v1`、`model_configs`（`native/src/state/population.rs`）
- `NamespaceMirror` のカウンター：木に届く書き込みのたびに変わります。`TickValidationMemo.begin` は符号化と設定の比較の代わりにこれを比べ、`==` は書き込みか丸ごとの代入の後だけ動きます。
- `runner.py` が毎分の始めに実行していた `model_configs !=`（約 50 µs/tick）もカウンターに変えました。
- 人口の動態の検査は、状態、人、区域が変わらず保留の人がいないときに省きます。
- 書き手（結果は同じ）：presence の履歴は 4 か所でその場に追記し、変わらない `pending_arrivals` は書き直しません。

`Geo::of` のカウンターによるキャッシュは試して外しました。約 14 µs/tick（0.5%）の効果に対し、スコープ内で設定をその場で変えると古い計画が残る恐れがあるためです。

## 分かっている弱点

- **検出が弱くなる点が 1 つあります。** `dict.__setitem__` が木の節点に直接書くと、以前は tick の検査の `saved_json` で見えましたが、今は次の完全検証まで見えません。テストで固定しています。`src/` にそのような書き込みはありません。
- 省略が誤っていても、ゲートは正しい状態しか持たないのでハッシュには出ません。感度の確認では、動態の省略の誤り、履歴の上限 20,000 → 20,200、runner が設定の書き込みを無視する誤りは、シャドーでもハッシュでも見えず、テストだけが検出します。動態の省略は最初の版のテストでは通ってしまったので、テストを書き直しました。カウンターが動かない誤りはシャドーとテストが検出します。
- 設定は `TrackedDict` になりました。今後の kernel が `downcast_exact` で読むと、黙って拒否します。`exact_dict` を使ってください。grep で確認した範囲では該当はありません。
- #338 の `apply_effect` との組み合わせは、読むだけで確かめ、マージ後のゲートと 7 日間のハッシュで確認しました。
- 待っている到着者がいる Run では、`_zone_has_room` が保留の人ごと・tick ごとに呼ばれます（ゲートで 84,949 回）。7 日間の経路には現れません。
- Linux 以外は CI に任せます。新しい C API はありません。
