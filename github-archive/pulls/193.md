## 元の本文

Closes #190

Runの記録（`manifest.json` など）で、モデルの出典のDOIが電話番号とみなされ `[REDACTED]` になる不具合を直します。相談のとおり、電話番号の検出を保存の検査と同じ定義に揃えます。係数は変えていません。

## 原因

電話番号の検出が2種類ありました。

| 場所 | 定義 | 一致するもの |
|---|---|---|
| `storage/projects.py`（保存の検査） | `\d{2,4}[- ]\d{2,4}[- ]\d{3,4}`（区切りのある3組。先頭の国番号は任意） | `090-1234-5678` など |
| `inspection/traces.py`（Run成果物）、`web/inspector.py`（保存したRunの表示） | `\+?\d[\d ().-]{7,}\d` | 数字と区切りが10文字以上並ぶもの全部 |

広い方は、DOIや日付にも一致します。生成Scenarioの Run では、インストール済みのモデルの出典4種類（DeGroot、Bosse、Kuppens、Hatfield）が `[REDACTED]` になっていました（ほかの値は伏せ字になっていなかった）。

## 変更

#187 のメールアドレスと同じく、1つの定義にまとめました。
- `storage/projects.py`：電話番号の検出を公開の定数 `PHONE_NUMBER` にした（定義は変えていない）。
- `inspection/traces.py`、`web/inspector.py`：自分の広い定義を消し、`PHONE_NUMBER` を使う。

| 値 | 直す前（Runの記録） | 直した後 |
|---|---|---|
| `doi:10.1080/01621459.1974.10480137` などのDOI | 伏せ字 | そのまま |
| `2026-10-28` | 伏せ字 | そのまま |
| 住所の番地 `押上3-46-17` | そのまま | そのまま |
| `090-1234-5678`、`03-1234-5678`、`+81 90 1234 5678` | 伏せ字 | 伏せ字 |
| `0312345678`（区切りなし） | 伏せ字 | **そのまま**（保存の検査は、もとからこの扱い） |

区切りのない番号を捕まえなくなるのが、この直し方の代償です。Projectに保存されるデータの検査は、もとからこの範囲でした。

## テスト

- 電話番号・メールアドレスを伏せ字にする既存のテストも通る。
