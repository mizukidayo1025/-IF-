## 元の本文

Closes #79

## 原因

一時外出と転送（`population_presence` の `temporary_exit`・`transfer`）では、その人の状態（情報、体の状態、人間関係など）が人口のライフサイクルの「預かり」（`population_lifecycle_v1.people`）に移り、在所者（`world.agents`）から外れます。

ところが、給水・配食の利用履歴（`resource_service_v1.request_history` と `queue_stall_history`）には、その人の記録が残ります。`WorldState.validate` は、履歴に出てくる人が在所者の中にいることを求めていました。そのため、一度でも給水・配食を使った人の外出は、検証で失敗していました。時間が経つとほとんどの人が使うので、ほとんどの人が外出できませんでした。

## 直し方

`WorldState.validate` で、預かりにいる人の記録も正しい履歴として認めるようにしました。

- 履歴は過去の事実の記録で、使われ方は監査と「並んだ時刻」の検索だけです。
- 預かりにいる人は、Runの中ではまだ存在していて、戻ってくることもあります。
- 退所（`depart_evacuees`）のように履歴から消すと、戻った人の過去の利用記録が失われます。そのため、その方法はとりませんでした。

在所者にも預かりにもいない人の記録は、これまでどおり不正と判定します。

## テスト

- `tests/integration/test_intervention_outcomes.py`：xfail にしていたテストを、外出して戻るまでを確かめる `test_someone_who_has_used_water_or_meals_can_go_out_and_come_back` に書き換えました。
  - 60分に配食を使った人（`A001`）が一時外出し、200分に戻る指示で在所者に戻る。
  - 外出前の利用記録（26分・31分の配食）が残っている。
  - 修正前のコードでは、外出が失敗するので戻る指示も却下され、失敗します。
- `tests/unit/core/test_world.py`（新規、2件）：在所者の記録は正しく、どこにもいない人の記録は今までどおり不正と判定されることを確かめます。
- `docs/testing.md` の地図、集計、xfailの例を更新しました。

一時外出の戻りは、予定の時刻（`expected_return_minute`）に自動では起きず、戻る指示（`action: "return"`）が要ります。これは今の設計どおりで、この PR では変えていません。
