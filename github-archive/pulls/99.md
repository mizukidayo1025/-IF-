## 背景

給水所と配食所は、施設と同じ区画にいて担当の技能を持つ職員だけが受け持ちます（`domain/resource_service.py`）。設備の移設（`transfer_equipment`）では職員が一緒に移らないので、給水所を避難スペースへ移すと、その後は誰も給水を受けられませんでした。しかも、介入は通ったように見えていました。

## 方針（A：承認前に却下する）

#83 では、次の3つを比べて A にしました。

- **A**：移設先に担当の職員がいなければ却下する。
- **B**：担当の職員も一緒に移す。
- **C**：職員が別の区画の施設まで出向いて受け持つ。

B と C は、誰を何人移すか、どう出向くかという運用モデルの設計そのものです。担当の方と相談してから、必要なら別のIssueで扱います。A は、黙ってサービスが止まる状態をなくし、利用者に理由を返す最小の変更です。

## 変更内容

- `domain/geometry_overlay.py`：設備の移設の検証（`validate_geometry_change`）に検査を足しました。給水所・配食所を移すときは、移設先の区画に担当技能の職員がいるかを確かめます。担当技能は `resource_service` の設定の `water_staff_skill`・`meal_staff_skill` と、提供地点が求める技能です。いなければ `staff_unavailable: no staff with water_service works in 'sleeping', so the moved station would not be served` のように却下します。
  - この検証は、承認前と適用時の両方で使われます。給水・配食の職員は作業で区画を移らないので、両方で同じ結果になります。
- `docs/effect-program.md`：操作の表に `transfer_equipment` を足し、この規則を書きました。

職員の要らない設備（トイレなど）の移設と、担当の職員がいる区画への移設は、これまでどおり適用されます。
