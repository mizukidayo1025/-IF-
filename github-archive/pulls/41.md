_Requested by **すみす**_

Before: On the demo-v2 simulation screen, the compute buttons were small and sat at the bottom of the timeline, while the large "▶ 再生" button looked like it would run the simulation. Timeline events scrolled sideways, were all drawn in red, and mixed English IDs (e.g. `staff_support_complete`) with vague Japanese labels. The issues panel told users to "check the records" without saying where. The evacuee/staff panel was a 140px box, and the report gave no visible sign that it was only a partial summary before the run finished.

After: Compute controls have their own enlarged panel between the map and the timeline. Play buttons read "▶ シミュレーションを再生". Timeline events sit under a "発生したスタッフ対応・避難者支援など" heading, wrap in a grid, are colored blue (resolved), red (unresolved/problem) or gray (progress record), and every event type has a plain Japanese name. The issues panel points to the event timeline. The intervention panel says to finish or stop computing first. Branch comparison puts a larger compute target next to the layer selector. Intervention headings use the same branch icon as the nav. The report shows an orange "簡易版レポート" banner until the run reaches its end. The evacuee/staff panel is larger, and selecting a person opens a status popup with labeled meters for mood and needs.

How: Front-end only (`demo-v2.html`, `demo-v2.js`, `demo-v2.css`). Event coloring is a client-side lookup by `event_type` plus `rejected`/`failed` status; no API, schema or simulation behavior changes. `tests/test_demo_v2.py` passes offline (12 tests). `git merge-tree` against current `main` (#40) reports no conflicts.
