## 元の本文

画面の再生用の frame の一括読み取り（`GET .../replay-frames`）を、返す内容を変えずに速くします。

## 修正前

最大8分ぶんの frame を、1〜2本の branch について返します。次の2つが重くなっていました。

- **分ごとの世界のハッシュ**: 各分の frame で `world.state_digest()`（世界全体の正準JSONのハッシュ）を計算していました。1440分の世界では1回約0.9秒かかり、8分×2本で約15秒になります。
- **最初の分の比較**: 2本の場合、共通の範囲・分岐の記録・共通の起点を得るためだけに `workspace.comparison()` を呼んでいました。これは各 branch の最初の分の frame を作る（保存境界の間なら、復元と再計算を含む）処理ですが、作った frame は使っていませんでした。

## 変更

- 各 branch の分ごとのハッシュを、Checkpoint 保存の履歴キャッシュ（`CheckpointHistoryCache`、#44）で計算します。続けて進む同じ世界なので、2分目からは前の分から増えた履歴だけを変換します。キャッシュが作る正準JSONは、全体を変換した場合とbyte単位で同じです（#44 のテストで確かめているもの）。検証もこれまでどおり各分で行います（`state_digest()` と同じ）。
- 比較の共通の範囲・分岐の記録・共通の起点は、frame を作らずに読みます（`ProjectWorkspace.comparison_context`）。`comparison()` もこれを使います。範囲外の時刻などを拒否する確認とメッセージは同じです。
