`tests/live/test_live_api.py::test_live_official_domain_search_returns_only_verifiable_source_candidates` が、台帳の口座を毎回同じID（`live-source-search-stream-qa`）で開いていたのを、実行ごとの `live-source-search-stream-qa-<乱数>` にしました。#148（PR #151）のモデル別確認と同じ直し方です。上限（2 call、予算10ドル）と確かめる内容は変えていません。全実行の合計は、これまでどおり端末の共有上限（task-global-v1、既定50ドル）が抑えます。

**固定の口座で起きること（Issueの見立ての訂正）：** #152 では「2 callの上限が通算になり、3回目から断られる」と見立てていましたが、offline で確かめると、**2回目で断られました**。このテストは毎回同じ入力のtaskを、毎回新しいテープで送ります。台帳は、同じ口座に同じ request key の receipt があると `usage_receipt_exists` で断る（`UsageLedger.reserve`）ので、固定の口座ではこのPCで最初の1回しか通りません。receipt が残るので、上限が通算になる問題もあります。

設定・口座・taskを作る部分は、`tests/conftest.py` の fixture `live_source_search_check` にまとめました。`tests/unit/llm/test_accounting.py` の offline テストが、web検索の引用を返す偽の Provider で、同じ記録先に3回続けて実行しても毎回予約・記録されることを確かめます。

`docs/llm-integration.md` の公式ドメイン検索の説明と、`docs/testing.md` のテストの地図を直しました。製品コードは変えていません。
