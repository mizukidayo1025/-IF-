## 概要

`domain/population.py` と `domain/population_lifecycle.py` の規則に Rust の経路を作りました。ゲートと 7 日間で結果は変わりません。ただし一部の規則は Python に残り、kernel が Python を呼ぶ箇所も残ります。

**7 日間では書き手が動きません。** ゲートでも数回なので、書き手の比較の大半はテストです。

速度のためではなく、手順 4 で Python の規則を消すためのレーンです。

詳細は `docs/rust-port/lanes/m6-population-rules.md` にあります。

## 移した処理

`native/src/rules/population.rs`、`population_lifecycle.rs`：到着の生成、`add_body_agent` の値、部屋の格子と距離、上限、`queue_arrivals`、`queue_departures`、接近の完了、再試行、`apply_presence_action`、移動の完了、`admit_pending_arrivals`、`admit_pending_returns`。

**書き込みの形（手順 4 で見直す点）：** kernel は最初の書き込みの前に計画と拒否を済ませ、その後で Python の規則と同じ操作を同じ順序で追跡コンテナに対して行い、それが行へ転送されます。少ないイベントでしか動かない規則なので、行に型付きで書く実装はしていません。追跡コンテナが手順 4 で残らなければ、書き込みの段階を書き直す必要があります。

**コールバックが残る箇所：** 出発を書いた後と移動の完了の後で、内側の受け入れが拒否されると、その 1 手順の Python の規則を `__wrapped__` で呼びます。書き始めた規則は最初からやり直せないためです。この経路の回数は数えていません。
