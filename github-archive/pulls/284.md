## 元の本文

## 概要

5倍高速化（100人・7日分を画面から計算）の5つ目です。毎 tick の検証のうち、社会関係（`social_network_v1`）と体調の関係（`body_state_v1`）の記録の確認を速くします。確かめる内容は変えません。

7日目には関係の記録が約9,800件あり、毎 tick すべてを確かめています。これまでは記録ごとに、フィールド名の集合を作り、ジェネレーターで回数を確かめていました。

## 変更

- **`domain/social_network.py` と `domain/body_state.py`：** 関係の記録の確認を、1件ずつ直接書きました。
  - フィールド名の確認：`set(record) != {...}` の代わりに、`record.keys() != _RELATIONSHIP_FIELDS`（定数の frozenset）で比べます。集合を作りません。
  - 回数の確認：ジェネレーターを使わず、1つずつ読みます。受け付ける値は前と同じです（社会関係は `int` で `bool` でない 0 以上の値、体調は型がちょうど `int` の 0 以上の値）。
  - 体調の関係の2人の確認と話題の確認も、同じく直接書きました。
- **変えないもの：** 受け付ける記録・誤りのメッセージ・確認の順序。

## モデル担当の方へ

検証のコードの書き方だけを変えました。どの記録を受け付けるかは前と同じで、それを確かめるテストを足しています（下記）。
