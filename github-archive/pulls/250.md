## 元の本文

承認した介入の適用で、分岐元の状態の確認を分岐の処理の中で行い、分岐元の復元を1回にします。

## 修正前

介入の適用（`intervention-apply`）は、次の順に処理していました。

1. プレビューの時刻に分岐元を復元し、世界のハッシュ（`state_digest()`）がプレビューのものと同じか確かめる
2. 分岐の処理（`fork`）で、同じ時刻にもう一度分岐元を復元する

保存境界の間の時刻なら、1回の復元に再計算も含みます。

## 変更

- 分岐の処理が作る分岐元の Checkpoint の `state_hash` は、1で確かめていたハッシュと同じ値です（PR #222）。
- そこで、`TimelineStore.fork` に `expected_state_hash` を追加し、分岐元の Checkpoint を作った直後、何も保存する前に比べます。違えば、これまでと同じメッセージ（`source state changed; preview the intervention again`）で拒否します。
- Project API の分岐の処理を `ProjectAPI.fork` にまとめ、分岐のルートと介入の適用の両方から使います。分岐のルートの振る舞い（受け付ける項目、承認の確認、計算中の拒否）は変えていません。
- 確認は、計算 worker の排他（`ProjectAPI._lock`）の中で行うようになりました。
