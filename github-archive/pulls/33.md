## 元の本文

## 概要
`SHELTERSIM_LLM_ERROR_POLICY=stop`でも、介入の自然言語変換だけがAPIの失敗を捕まえてルール処理（offline parser）の結果を返していました。`docs/ui-backup.md`は「API接続、利用枠、応答検証で失敗した場合はfallbackせず、エラー理由を表示します」と定めており、その仕様に反していました。

## 変更
- stop設定かつoffline mode以外でOpusの案を使えなかった場合、compilerは`InterventionCompilerUnavailable`を送出します。理由は、fallback時に`limitations`へ入れる日本語の固定文と同じです。応答検証の失敗では、従来どおり1回の修正依頼をしてから失敗します。
- Project APIのintervention-previewは、409と`code: intervention_compiler_unavailable`で理由を返します。以前のstop時の他機能のように、汎用の500「project operation failed」にはなりません。
- legacyの`/api/v1/nl/interpret`は409で理由を返します。
- 明示したoffline modeでは、stopでもルール処理の結果を返します。fallback設定の動作は変わりません。
- `docs/adaptive-event-compiler.md`、`docs/llm-integration.md`、`docs/api-reference.md`を更新しました。

## 確認（すべてローカル）
- `SHELTERSIM_LLM_MODE=offline .venv/bin/python -m pytest -n auto`：800 passed、3 skipped（live API test）
- legacy demoのテストは、修正前のコードで失敗することを確認しました（修正前は200でルール処理の結果）。compilerとProject経路のテストは新しい例外を使うため、修正前のコードではimportの段階で失敗します。
- 変更したファイルのruff check指摘は、すべてmainと同数です。
- 実APIは呼んでいません。

PR #32（offline parserの修正）とは独立しています。
