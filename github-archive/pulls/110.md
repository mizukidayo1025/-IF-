## 変更内容

`docs/testing.md`「既存のテスト」の手順どおり、2つのコミットに分けています。

1. **`git mv` だけのコミット**：`tests/unit/web/test_workspace.py` に移し、`UNSORTED` から消しました。世帯の修正の経路は `src/sheltersim/web/workspace.py` にあるので、その名前に合わせています。
2. **内容の変更**
   - これまでのやり方：`InitialScenarioBuilder` で seed 42 の下書きを作り、内部のキャッシュ（`_cache`）に直接入れていました。生成された人（6歳の `A005`、世帯 `H000002`、親 `A002`、「未成年者が3人」）をIDで固定して確かめていました。
   - 新しいやり方：画面と同じ `scenario-preview` の経路で下書きを作ります。修正できる未成年者・その世帯・親になれる大人を下書きから探して確かめます。人数の文言も、下書きから数えた値で確かめます。
   - 全員を修正すると未成年者の問題が消えることを確かめる1件は、共通の seed では成り立ちません（同じ世帯に大人のいない未成年者が1人できる）。この1件は元と同じ seed 0・10人を、プレビューの経路に渡しています。
   - 古いキャッシュ（承認の妨げを記録していない下書き）を拒むことを確かめる1件は、意図してキャッシュに直接入れたままです。中身のScenarioはプレビューで作ったものを使います。

### 共通fixtureの追加（`tests/conftest.py`）

プレビューを作った同じ ProjectAPI で修正の経路を続けて呼ぶ必要があります。今の `generated_previews` はプレビューを作ると ProjectAPI を閉じるので、次の2つを足しました。

- `ui_project_api`：地域調査を空に差し替えた ProjectAPI（project名 `project`）を、テストの間だけ開いておく。
- `generated_request(**fields)`：共通の入力欄の値を返す。

共通のプレビュー（`generated_previews`）も同じ組み立てを使う形にまとめました。固定された実行結果（`generated_small`）は変わりません。`docs/testing.md` の共通fixtureの節に、この2つと「画面にない項目も渡せる」ことを書き足し、地図も更新しました。

確かめている内容は変えていません。
