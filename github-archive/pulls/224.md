## 元の本文

保存とhistory indexの個人情報の検査と、indexの検証器の組み立てを、結果を変えずに速くします。

## 変更

- `safe_document()` は、保存する記録とindexの行に含まれるすべての文字列に、正規表現を2回かけていました。同じIDやラベルが何度も出てくるため、128文字以下の文字列は一度だけ検査して結果を覚えます（`functools.lru_cache`、16,384件まで）。長い文字列と `str` のサブクラスは、これまでどおり毎回検査します。辞書のキーの検査も、ジェネレーターを使わないループにしました。
- history index は、運用・待ち行列の記録1件ごとに pydantic の `TypeAdapter` を作り直し、待ち行列のイベント1件ごとに施設形状を解析していました。`TypeAdapter` は型ごとに1回だけ作り、施設形状は1回の登録につき1回だけ解析します。
