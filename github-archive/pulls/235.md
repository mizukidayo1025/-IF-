## 変更

`validate_body_state` は、保存された設定（`state["config"]`）が「正規化した設定から、古い版が書かなかった省略可能な項目をいくつか除いたもの」に一致するかを確かめています。

- 修正前は、省略可能な項目（13個、Policy Registry で感情モデルを選ばない場合は14個）のあらゆる組み合わせについて、項目を除いた設定の辞書を作って並べ（最大 2^14 = 16,384 個）、そのリストに含まれるかを調べていました。この検証は毎tick走ります。
- 修正後は、次の3つを直接確かめます。
  - 保存された設定のキーが、正規化した設定のキーの部分集合であること
  - 足りないキーが、すべて省略可能な項目であること
  - 残ったキーの値が一致すること（辞書の比較と同じく、同じオブジェクトか `==` で等しいこと）
- 受け入れる設定と拒否する設定は、修正前と同じです。
- 2つ目のcommitでは、関係（`relationships`）のキーの解析（`json.loads` と、`json.dumps` で書き戻した比較）の結果を、文字列のキーごとに覚えます（`functools.lru_cache`、65,536件まで）。キーが今いる避難者を指すかは、これまでどおり毎回、同じ順番で確かめます。
- 数式・係数・乱数・tick順序は変えていません。
