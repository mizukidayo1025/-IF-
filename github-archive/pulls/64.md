## 概要
テストの置き場所と名前の決まりを作り、守られているかをテストで確かめるようにしました。既存ファイルは一括では移さず、変更するときに移します。

## 決めたこと（`docs/testing.md`「テストの置き場所と名前」）
| 置き場所 | 範囲 | 名前 |
|---|---|---|
| `tests/unit/<担当>/` | 単体：`TickEngine` で時間を進めず、HTTP・CLIも通さない | `test_<srcのモジュール名>.py` |
| `tests/integration/` | 統合：時間を進めるか、HTTP・CLIを通す | `test_<機能>.py` |
| `tests/e2e/` | e2e：HTTPかCLIから入り、時間も進める | `test_<利用者の流れ>.py` |
| `tests/live/` | 有料APIのライブテスト | `test_live_api.py` だけ |

- **担当**：AGENTS.mdのモジュール、`cli`、リポジトリ自体を確かめる `repo` のどれかです。
- **名前**：不具合名、開発の回の名前、`regressions` は使いません。再発防止テストは、その機能のファイルに足します。
- **目的（結果・契約・画面）**：ディレクトリにも、pytestの印にもしません。実行の選び分けに使わない印は、付け忘れても気づけず、実態とずれやすいためです。関数名と地図の「目的」欄で把握します。
- **時刻を手で動かす単体テスト**：書いてかまいません。ただし、tickの順序で決まる振る舞いは、`TickEngine` で時間を進める統合テストでも確かめます。KPIや比較を確かめるために、イベント記録を手で書き込むことはしません。
- **既存ファイルの移し方**：まず `git mv` だけのcommitを作り、内容の変更は次のcommitにします。範囲が混ざるファイルは、移すときに分けます。
