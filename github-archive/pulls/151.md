## 変更内容

`tests/live/test_live_api.py::test_live_opus_sonnet_and_haiku_calls_are_durably_capped_and_replayable` が通らない原因は2つありました。上限（3 call・0.15ドル）は変えていません。

1. **呼ぶ順番（#148 の原因）：** runtime の呼び出しは分析用の枠（`ANALYSIS_RESERVED_CALLS`）を残す必要があり、3 call の口座では最初の1件でしか予約できません。Haiku（runtime）を最初に、Opus・Sonnet をその後に呼ぶ順番にしました（#148 の案1）。モデル順の確認も `[haiku, opus, sonnet]` に直しています。
2. **固定の口座（直す途中で見つけた原因）：** 台帳の口座IDが毎回 `live-task-qa` で、receipt が実行をまたいで残るので、3 call の上限が「このPCで通算」になっていました。前回の実行で使った分が残り、順番を直しても2回目以降は必ず断られます。実行ごとに `live-task-qa-<乱数>` の口座を作るようにしました。全実行の合計は、これまでどおり端末の共有上限（task-global-v1、既定50ドル）が抑えます。利用者の判断を得て、こちらにしました。

`docs/llm-integration.md` のモデル別確認の説明と、`docs/testing.md` のテストの地図を直しました。製品コードは変えていません。
