## 元の本文

移植の系統がハッシュを壊したときに、**どの分の、どの段階の、どの名前空間の、どの値か**が分かるツールを入れます。`src/` は変えていません。

## 追加するもの
- `benchmarks/first_difference.py`: 各段階の後の名前空間ごとの digest を2つの Run で比べて、最初の差と値（16 進の浮動小数まで）を示します。`--both` は Rust ありと Python で自動的に比べます。
- `benchmarks/tick_probe.py`: digest と、乱数ごとの「キー、値、比べた値」の記録です。
- `gate_all_paths.py --reversed-order`: 各段階の終わりに dict の順を逆にして、結果が順に依存しないことを確かめます。

## 出力の例（`query_pressure` の減衰に 1.5 倍のバグを入れた写し）
```
digests: first difference at line 41 of the streams
  A: engine 0, minute 5, phase sample_endogenous_events
  parts that differ (1): model_state/information_spread_v1
  model_state/information_spread_v1.query_pressure.A001
    A: 0.498 (float 0x1.fdf3b645a1cacp-2)
    B: 0.497 (float 0x1.fced916872b02p-2)
```

## 全経路の確認で検出できなかった 1% の差も検出できます
| 変更（`src` の写しに当てる） | 差のある乱数 | 判定が変わった数 | 最初の差 |
|---|---:|---:|---|
| 忘れる確率 +1% | 9,697 / 117,896 | 0 | 5 分、`sample_endogenous_events` |
| 訂正の受け入れ確率 -1% | 59 / 117,896 | 0 | 60 分、`dispatch_due_events` |

**制約:** Rust の中で引いた乱数は記録されません。式を Rust に移したら、`docs/rust-port/lanes/p0-digest.md` の手順で `test_native_kernels.py` にビット比較を足す必要があります。

## 結果
- Rust ありと Python（`--both --draws`）: 55 Scenario すべてで digest と乱数に差はありません（Rust の中の乱数を除く）。
- dict の順の逆転（各段階の終わり）: 55 Scenario すべてでハッシュは同じです。段階の途中の逆転は 54 が同じで、`generated_project` は負荷による `wait_idle` の時間切れで止まり、単独の再実行では同じでした。
- **これは手順 4 の並列化の証拠にはなりません。** 多くの規則は ID を並べ替えてから処理するので、dict の順を変えても処理の順は変わりません。

## 注意
- digest の遅さ: 1 日分で約 4.5 倍。`--every-minutes` で粗くできます。`--draws` の出力は大きいです（全経路で約 6 GB）。
- 追記専用の履歴は項目ごとに 1 回だけハッシュします。古い項目の書き換えは次の全体の再ハッシュ（既定 60 分ごと）で見つかります。
- `world_parts` は非公開の `WorldState._canonical_data` を使います。P6 で残すか、probe を直す必要があります。
- `gate_scenarios.py` の `wait_idle` の上限を 600 秒から 7200 秒にしました。動かなくなった Run を止めるためだけのものです。
