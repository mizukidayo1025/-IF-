## 元の本文

## 背景

#57 の地図（`docs/testing.md`「テストの地図」）の穴8で、生成Scenarioを実行する遅いテストに `long_simulation` の印がないことが分かっていました。#53 を閉じるときも「そのまま」として残していました。

## 変更内容

生成Scenarioを1日分実行する4件に `@pytest.mark.long_simulation` を付けました。時間は直列で計ったものです。

| テスト | 時間 |
|---|---|
| `test_queue_service_while_repositioning.py::test_one_meal_station_keeps_up_with_one_hundred_people` | 約85秒 |
| `test_standard_provisioning.py::test_default_generated_scenario_serves_water_and_meals` | 約39秒 |
| `test_physical_queue_overflow.py::test_staffed_water_station_serves_a_queue_longer_than_its_room` | 約39秒 |
| `test_resource_queue_regressions.py::test_generated_scenario_with_entered_stock_completes_a_day` | 約39秒 |

印を付けなかったもので一番遅いのは、`test_care_lifecycle.py` の1日分のテスト（約21秒）です。境目は30秒にしました。

- `pyproject.toml` の印の説明を「7日間のsimulationと、1件で30秒以上かかるテスト」に広げました。前から印のある4件は7日間のテストで、うち2件（約7秒と約2秒）は30秒未満です。
- `docs/testing.md`
  - 並列実行の節に、印の範囲、CIでの扱い、実行時間を追記しました。
  - 「既存のテスト」に「`long_simulation` の印を付けるだけの変更では、ファイルを移さない」と追記しました。4本とも `tests/` 直下の既存ファイルで、単体と統合が混ざっています。移動と分割は、#88 などで改めて行います。
  - 地図の印の欄と、穴8を更新しました。

## 影響

- 印のない `pytest` は、これまでどおり全件を実行します。
- 手動実行の `オフラインCI`（`ci.yml`、`-m "not long_simulation"`）からは、この4件が外れます。`長時間simulation回帰`（`long-regression.yml`）の `long` と `full` では実行されます。CIの設定は変えていません。
