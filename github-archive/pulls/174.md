## 元の本文

Closes #160

Project画面の介入（承認済みのEffectProgram）で分岐したBranchのPDFレポートに、介入の数量が出るようにします。例：仮設トイレの台数（`count`）、物資の量（`quantity`）。

## 原因

`collect_report` は、介入の `details` に残すpayloadのキーを決め打ちしていました。EffectProgramのイベントは、操作によってパラメーターを `parameters` の下ではなく、payloadの直下に置きます。そのため、直下に置かれた数量が落ちていました。

## 落ちていたもの

調べると、`count` と `quantity` のほかにも落ちていました。

| 操作 | payloadの直下に置くパラメーター | 直す前に残っていたもの |
|---|---|---|
| `add_toilet`・`add_staff` | `count` | `op`・`zone_id` |
| `add_evacuees` | `count`・`household_size`・`mobility`・`language`・`admission_zone_ids`・`approach_route_id`・`person_context_overrides` | `op`・`zone_id` |
| `depart_evacuees` | `count`・`include_initial` | `op`・`zone_id` |
| `deliver_resource` | `warehouse_id`・`resource_id`・`quantity` | なし |
| `modify_supply_schedule` | `shipment_id`・`to_minute` | なし |
| `set_staff_availability` | `staff_id`・`until_minute` | なし |

ほかの操作は、パラメーターを `parameters` の下にまとめて置くので、今までも残っていました。

## 変更

- `web/pdf_report.py`：キーの選び方を `intervention_details(payload)` に切り出した。残すキーに `count`・`quantity`・`resource_id`・`household_size`・`include_initial`・`to_minute`・`staff_id`・`until_minute` を足した。
- `web/pdf_render.py`：足したキーにPDFでの表示名を付けた（例：`resource_id` は「物資」）。`count`・`quantity` の表示名はもともとある。
- 分析用のfacts（`analysis_facts`）は、もともと `count`・`quantity` を拾う作りなので、変えていない。

レポートの「個人profileを含めない」方針のため、次は載せません。
- 追加避難者の `person_context_overrides`（個人ごとの文脈）
- `language`、経路（`admission_zone_ids`・`approach_route_id`）、`mobility`
- 倉庫・出荷のIDと、内部のprogram・effect・modifierのID

## テスト

- `unit/web/test_pdf_report.py` に2件足した。
  - `test_effect_program_interventions_keep_their_top_level_quantities`：トイレ・物資・配送の変更・スタッフの不在の各形で、数量が残る
  - `test_arriving_evacuees_report_their_count_without_person_context`：追加避難者の人数と世帯人数は残り、個人ごとの文脈・言語・経路は残らない
- `integration/test_pdf_report.py`
  - #137 で `xfail` にした生成ScenarioのEffectProgramのテストの印を外した。
  - PDFを組むテストに、本文に「数: 2」が出ることの確認を足した。
- 直す前のコードでは、統合テスト2件が失敗することを確かめた（単体テストは、関数がまだないので import で止まる）。

これで、テストに残っていた `xfail` はなくなりました。
