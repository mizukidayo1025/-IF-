## 元の本文

## 概要

M2 の最後のレーンです。行動の判断を記録する処理を Rust へ移しました。通常の tick では `ActionProposal` を作りません（テストで固定）。trace が有効な Run では、従来どおり Python の手順で作ります。

詳細は `docs/rust-port/lanes/j-decisions.md` にあります。

## 移した処理（`native/src/rules/decisions.rs`）

- `_propose_due` → `propose_rows`。`_apply_proposal` の本体が読む5項目だけを `ProposalRow` で返します。`candidates` などを読むときに限り、`ActionProposal` を1回作ります。
- `_observed_state` → `observed_row`
- `_apply_proposal` の末尾を `_record_outcome` として分離し、`record_outcome` へ移しました。順序は `record_decision`、`commit_action`、`remember_decision` です。
- `_IndexedMetricSink` の行を JSON のバイト列のまま `observations` へ渡します。
- `_apply_proposal` の本体は移していません。`wait` と `rest` は 7 日間の 87,464 件の判断のうち 7.1% だけで、簡単な行動だけを先に移す利点が小さいためです。

拒否できる処理はすべて行の追加より前に行うため、Python の手順に戻っても二重には実行されません。追加後に `commit_action` か `remember_decision` が拒否した場合は、その規則だけを Python で実行します。trace が有効な Run の文書は Python が書き、`decisions.jsonl` のバイト列が一致することをテストで確認しています。
