## 元の本文

## 概要

WorldState v5 の世界の毎 tick の検証を、v6 と同じ Rust の経路で行うようにしました。ゲートの v5 の拒否は 2,320 → 0 です。ハッシュ、ゲート、7 日間は変わりません。

L9 で分かったとおり、v5 は旧形式ではありません。資源サービスのない Scenario では今も書かれます。棚卸しの分類も直しました。

詳細は `docs/rust-port/lanes/l7b-world-v5.md` にあります。

## v5 と v6 の検証の違い

Python のコード（`validate`、`_validate_entity_rules`、`to_dict`、`from_dict`）を読んで確かめました。違いは資源サービスだけで、ほかの名前空間と規則は同じです。

- v5 には、`resource_service` の設定、`resource_service_v1` の状態（禁止）、資源の枠（保存の文書にも入りません）、資源のタスク、サービスの予約がありません。
- 台帳は、v5 では `initial_stock` があるときだけ、v6 では常にあります。
- 水分の必要は、v5 では `hydration_need` と `initial_needs.hydration_need` の両方が 0 である必要があります。
- 給水と配食の地点は、v5 では通常の列を使えますが、v6 では禁止です。
- Python の癖：v5 の世界で無効なタスクへの `resource_service_complete` が保留にあると、`StateInvariantError` ではなく `KeyError` を出します。

## 変更

- `entity_rules` と `after_tick.rs` が v5 と v6 を受けます。
- `tick_plan` は `resource_service` がなければ `resource_config=None` を返します。
- 実体の規則は、v6 では資源の設定があるときだけ、v5 では設定がないときだけ受けます。
- 候補にした v5 の規則のうち 2 つ（「v5 の設備が資源の枠を持つ」と、`after_tick.rs` の版と設定の確認）は、ほかの規則が同じ状態を必ず捕まえ、必要だと示すテストが書けないので入れていません。
- エラー文と係数は変えていません。`core/errors.rs` と `core/kernels.py` は触っていません。

## 感度

実体の規則は、行ではなくオブジェクトを読むままです（T のレーンの指摘）。`test_entity_rules_kernel.py` と `test_after_tick_kernel.py` に v5 の節を足し、既存の壊し方の表（実体 34、tick 35）も v5 の世界で動かします。v5 だけの壊し方と、それぞれ 300 回のランダムな書き込みも足しました。

v5 で各規則を外せる感度用のビルドを作り、外すとどの規則も 1 件以上のテストが失敗することを確かめました。例外は「v6 には資源の設定が要る」で、最初はどのテストも失敗しませんでした。テストの世界で水を受け取っている人がいて、別の経路が拒否していたためで、サービス中の人がいない世界に移したところ 2 件失敗するようになりました（`f74715b`）。

## 分かっている弱点

- ゲートの v5 の世界はすべて旧来の形（名前空間なし、トイレだけ）です。台帳や給水・配食の地点のある v5 の世界はテストだけです。
- 通常の列を使う v5 の給水の地点は、テストで作った状態だけにあります。
- 7 日間は v6 だけです。行の網羅は測っていません。Linux 以外は CI に任せます。

## 手順 4 に残るもの

- `operational_kpi_values` は v5 で `ValueError` を出し、`kpi_values` は v5 を拒否して Python に任せます。
- v5 の資源の完了での Python の `KeyError` に、手順 4 でどの Rust の文を当てるか決める必要があります。

## モデル担当の確認事項

Rust だけの条件（当たると Python が判断します）：v5 の水分の値が小数でない場合（整数の 0 は拒否しますが、Python の `!= 0.0` は通します）、v5 の `resource_service_complete` イベントすべて、v5 に資源の設定を渡した場合と v6 で設定がない場合。
