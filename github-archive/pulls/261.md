## 変更

計算中、保存の直後に計算済みの時刻の frame を読むと、`TimelineError: no checkpoint exists before requested minute` で失敗することがありました（#259）。

- **原因**：保存（`TimelineStore.record`）は、Branch のポインタを新しい head に書き換えてから、履歴索引に登録します。その間に読み取りが来ると、索引の head がポインタと一致しないので `history_index_stale` になります。すると、旧形式の Run のための `timeline.json` を読む経路に進みます。新しい Run にはこのファイルがないので、今の head より前の時刻で候補がなくなっていました。
- **修正**：`HistoryIndex.nearest` は、索引の head がポインタの head より前の時刻にあるときも答えるようにしました。
  - ポインタの head の時刻以上を求められたら、ポインタの head を返します。
  - それより前の時刻は、索引にある Checkpoint から引きます。
  - 保存済みの Checkpoint は変わらず、Branch は先へ伸びるだけなので、索引の head までの答えは変わりません。
- 索引の head がポインタより先にある場合や、索引に head がない場合は、これまでどおり `history_index_stale` として扱います。

## 確認

保存と索引への登録の間に読んだ結果と、登録が済んでから読んだ結果を比べました。

| 読み取り | 修正前 | 修正後 |
|---|---|---|
| frame（保存境界・境界の間・新しい head） | 新しい head より前の時刻で失敗 | 登録後と同じ |
| 2本の比較（`compare`） | — | 登録後と同じ |
| 2本の再生（`replay-frames`） | — | 登録後と同じ |
| 履歴の検索（`history`） | `history_index_stale` | `history_index_stale`（変わらず） |

#259 を見つけたときの計測（1200分から1440分へ計算する間、1170分と1185分の frame を読み続ける）でも、読み取りの失敗は0回になりました。

|---|---|---|
| スレッド | 205回、287回 | 0回、0回 |
| 別プロセス | 0回、25回 | 0回、0回 |

## 残ること

履歴の検索（`GET …/history`）は、この間に `history_index_stale` で失敗します。検索は、ページ送りの cursor と件数を索引の head に結び付けているため、同じ直し方では済みません。#259 の完了の条件（frame・比較・再生）の外なので、この PR では扱いません。
