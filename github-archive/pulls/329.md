## 元の本文

## 概要
行動の周期（`domain/action_lifecycle.py`）と `agent_dynamics_v1`（`domain/agent_dynamics.py`）を Rust へ移します（`rules/action_lifecycle.rs`、`state/agent_dynamics.rs`）。イベントの記録はレーン E の `EventWriter` で書きます。各 kernel は先に全部の記録を計画し、断るときは何も変えません。詳細は `docs/rust-port/lanes/f-action-lifecycle.md` にあります。

`agent_dynamics_valid` をやめ、行の kernel（`state.agent_dynamics.validate`）で置き換えます。ルートのテストは `test_tick_validation_routes.py` に加えました。

## 直したもの
- `EventWriter::record` が負の `realized_minute` を受け入れていました。`EventLogRecord` は断るので、ログを復元できなくなります。同じ文のエラーにします。
- イベントの番号が `2**63` 近くになると、Rust の加算が release で黙って一周します。`2**62` を超えたら断り、Python の規則が動きます。
- `agent_dynamics_v1` の木から `dict.pop` で記録を消した世界で、`record_proposal` が `RuntimeError` を出し、ほかの書き手は行だけ変えていました。`Unsupported` を返します。

- 7日分：world `69aba6590f6b`、events `5e4c7645ef7f`、KPI `94c8cbb26041`（Python と同じ）

`461edb2`（コードは同じ）：

## 確かめていないこと
- `abandoned` の受領はゲートにも7日分にも現れず、テストの小さな入力だけが比べています。

- `EventWriter::settle` は本番で使っていません（M3 が最初です）。Run の最後に lifecycle のオブジェクトを作る費用と、7日分の RSS は測っていません。
